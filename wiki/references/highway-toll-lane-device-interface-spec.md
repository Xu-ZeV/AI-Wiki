## 1. 文档背景与试点范围

《高速公路联网收费系统优化升级收费站标准化专项试点技术方案 附件3 车道设备接口规范》（最新修订版本 V1.97，编制单位：**交通运输部路网监测与应急处置中心**，2026年10月，全书共94页）是国家高速公路联网收费系统“优化升级与收费站标准化专项试点”的核心技术准则。

### 1.1 核心编制目标
1. **解决协议碎片化**：终结各省收费站外设协议各立标准、互不兼容、集成改造成本高昂的痛点。
2. **统一站道物联接口**：标准化车道外设（TCP 客户端）与站级交易系统（TCP 服务端）之间的数据传输协议与控制语义。
3. **支持一体化与模块化**：既支持独立物理外设（单 IP 单模块），也原生支持一体化外设（单 IP 多功能模块或多 IP 组合控制）。
4. **支撑全国一张网高质量运营**：为 ETC 快速交易、CPC 卡高可靠流转、动态计重、数字孪生、移动扫码与自助无人化收费提供全国统一的协议基础。

## 2. 外设功能模块类型编码体系（E1H ~ F4H）

规范在第 2 节确立了覆盖全车道感知、控制、交易与交互设备的统一功能模块编码字典（采用十六进制表示）：

| 模块编码 | 外设功能模块名称 | 核心职能与交互特征 | 常见物理形态 |
| :--- | :--- | :--- | :--- |
| **E1H** | **RSU 路侧单元** | 5.8GHz 微波通讯，负责 ETC OBU 识别、CPC 唤醒与交易 | 龙门架天线 / 车道侧挂微波天线 |
| **E2H** | **高清车牌图像识别设备** | 车牌定位、字符识别、置信度、颜色判定、抓拍上传 | 车道前置牌照识别抓拍一体机 |
| **E3H** | **车型识别设备** | 轴型、轴距、车宽、车高、车辆长宽高轮廓与三维扫描 | 激光扫描仪 / 3D 轮廓摄像机 |
| **E4H** | **电动栏杆机** | 快速抬杆、落杆、到位信号上报、防砸车检测 | 智能快速变频栏杆机 |
| **E5H** | **车辆检测器** | 抓拍线圈、存在线圈、落杆线圈有车/无车状态监测 | 地感线圈检测器 / 微波车检器 |
| **E6H** | **信息显示屏（费显）** | 费额显示、车型车牌提示、通行指示与文字字幕 | 柱体式或一体式高亮 LED 费显屏 |
| **E7H** | **通行信号灯** | 车道红绿通行指示（红灯禁行/绿灯放行） | 栏杆立柱信号灯 |
| **E8H** | **报警器** | 非法闯卡、冲关、黑名单声光报警触发 | 声光蜂鸣报警一体装置 |
| **E9H** | **LED 情报板** | 车道诱导信息、站级综合文字诱导与限速提示 | 车道入口情报显示屏 |
| **EAH** | **雨棚信号灯** | 站前雨棚顶部红叉/绿箭指示车道启闭状态 | 悬挂式车道雨棚红绿灯 |
| **EBH** | **雾灯** | 恶劣天气轮廓引导、长亮/频率可调闪烁 | 诱导防雾灯具 |
| **ECH** | **称重检测设备** | 动态计重、轴型（1~9类）、轴重、总重与超限检测 | 入口石英/光纤计重弯板与秤台 |
| **EDH** | **自助发卡设备** | 入口司机按键取卡、预备卡、坏卡回收、机芯通道管理 | 智能自助发卡机器人/一体机 |
| **EEH** | **自助交费设备** | 出口 CPC 卡插入、收卡、验卡、票据打印与通行引导 | 智能自助交费一体机 |
| **EFH** | **车道摄像机** | 实时全景视频监控、字符叠加（OSD）、RTSP 推拉流 | 车道高清半球/枪机监控摄像机 |
| **F0H** | **非接触 IC 卡读写器** | 13.56MHz 射频读写、CPC 消费、PSAM 安全认证 | 台式或嵌入式非接触读写终端 |
| **F1H** | **票据打印机** | 通行费发票打印、进纸、切纸、卡纸与缺纸状态上报 | 热敏/针式发票打印模块 |
| **F2H** | **支付受理终端** | 银行卡、ETC 刷卡、银联闪付交易与冲正撤销 | 银联通过认证支付终端 |
| **F3H** | **扫码终端** | 微信/支付宝/银联等付款码主动与被动扫码识别 | 嵌入式高灵敏度二维扫码模组 |
| **F4H** | **语音播报设备** | 通行语音提示、费额播报、TTS 动态语音合成 | 数字化音频功率放大模块 |
| **F5H~FFH** | **预留编码** | 供未来新型车道感知与自动驾驶协同外设扩展 | 行业统一标准扩充区间 |

### 2.1 模块唯一寻址与多模块一体机约定
- **寻址双元组**：`DeviceType`（1字节） + `DeviceIndex`（1字节序号，如 01H、02H）。当一条车道配有多个同类设备（如 3 组车检器），统一以 `E5H+01H`、`E5H+02H`、`E5H+03H` 严格区分。
- **一体化复合外设**：例如“多功能栏杆一体机”单台物理硬件包含栏杆机（E4H）、费显屏（E6H）、通行信号灯（E7H）与报警器（E8H）。可分配单个 IP 地址，支持在单条功能数据帧内进行多模块组装与复合并发控制。

## 3. 通信协议架构与数据帧规范

### 3.1 物理层与传输层约定
- **接口形态**：标准 RJ45 以太网，100M/1000M 自适应。
- **传输协议**：TCP 传输控制协议，外设为 TCP Client，站级交易系统为 TCP Server（工作模式）。
- **默认网络参数**：出厂默认 IP 为 `192.168.1.100`，监听/通信功能端口为 **`9528`**。
- **字节序准则**：所有多字节无符号数值均采用**大端模式（Big-Endian，高位字节在前，低位字节在后）**。未定义或保留字段默认填充 `00H`。

### 3.2 通讯数据帧结构（统一报文帧）
服务端与客户端通信的数据帧封装格式如下：

$$\text{Frame} = [\text{STX}] + [\text{VER}] + [\text{SEQ}] + [\text{LEN}] + [\text{DATA}] + [\text{CRC}]$$

| 字段名称 | 字节数 | 取值/编码 | 详细语义说明 |
| :--- | :--- | :--- | :--- |
| **STX** | 2 | `FFFFH` | 帧起始标志，固定双字节十六进制常数。 |
| **VER** | 1 | `00H` | 协议版本号，当前统一为 `00H`。 |
| **SEQ** | 1 | `01H~09H` / `10H~90H` | **帧序号交互对齐机制**：<br>• 服务端主动发送帧：`0XH`，外设响应帧亦为 `0XH`（保持一致，X取值1~9）；<br>• 客户端主动发送帧：`X0H`，服务端响应帧亦为 `X0H`（保持一致）；<br>• 每次通信交互自动递增，多轮交互（如 RSU 流程）步进加 1。 |
| **LEN** | 4 | 无符号整型 | DATA 域长度。高 2 字节保留填 `0000H`，低 2 字节表示 DATA 实际有效字节数。 |
| **DATA** | N | 十六进制字节串 | 具体的业务指令或数据域内容，由各功能接口具体定义。 |
| **CRC** | 2 | `0000H~FFFFH` | **CRC16-CCITT 校验值**：校验范围为**从 VER 到 DATA 最后一个字节**的所有字节。初始值为 `FFFFH`，多项式系数为 `0x8408`。 |

## 4. 设备配置与通用运行机制

规范将外设生命周期划分为两大模式：

### 4.1 出厂配置模式（车道设备 = Server，配置工具 = Client）
刚上电或工程部署阶段，外设作为服务端监听 9528 端口：
1. **0AH / A0H（设备 IP 设置）**：写入车道 HEX 编号（网络号 2B + 站点号 2B + 车道号 1B）、设备唯一认证码（CertificationInfo 8B）、目标 IP、子网掩码、网关与服务器 IP/端口。
2. **0BH / B0H（参数配置）**：批量下发外设各功能模块参数（如栏杆杂波滤波时长、牌识/车型上传模式 Flag 与 HTTP/FTP 目标目录、RTSP 串流地址）。
3. **1EH / E1H（参数采集）**：反查核验外设配置有效性。
4. **0DH / D0H（设备重启）**：配置确认后指令触发软重启，自动切换进入正式生产的【工作模式】。

### 4.2 工作运行模式（车道设备 = Client，站级交易系统 = Server）
外设主动连接站级交易系统服务端口，执行标准化四步接入：
1. **设备验证（0EH -> E0H）**：外设上电连通后首报验证帧，提交 LaneHex、CertificationInfo，站级系统鉴权合法后返回放行。
2. **设备初始化（1AH -> A1H）**：站级系统在 1 秒内下发工作模式初始化指令，配置 RSU 运行模式（集成 01H / 透传 02H）、加密算法（3DES 00H / SM4 04H）、天线功率与信道。
3. **状态监控心跳（0CH -> C0H，5秒周期）**：外设每隔 5 秒上报全局运行时间、连接状态、内存占用率、温度及各模块专属个性化监控数据。
4. **断网缓存与重传机制**：当网络闪断或超时未收到应答时，外设必须在本地积压队列中持久化（最大重传次数及重传时间间隔动态可配），待链路恢复后优先保序补发。

## 5. 核心车道外设功能接口详析

### 5.1 RSU 路侧单元接口（E1H）
车道级 ETC 交互的物理中枢，支持【集成模式】与【透传模式】：
- **服务端下行控制指令**：
  - `C1H`（继续交易）：确认微波信息，指令路侧单元继续读取车载单元。
  - `C2H`（停止交易）：终止当前交易流程或要求重发。
  - `C4H`（开关 RSU）：软件级打开或关闭微波发射天线。
  - `C6H`（ETC 交易扣费指令）：下发扣款金额、交易时间 TransTime、终端机编号，指示 RSU 执行 PSAM 消费运算。
  - `C7H`（计算 MAC1 返回）：针对全网在线密钥中心体系，下发中心计算生成的 MAC1。
  - `CCH` / `CDH`（重取 TAC 及其在线 MAC1）：处理因异常掉电或通讯丢失时的 TAC 幂等补验。
- **RSU 上行数据帧**：
  - `B0H`（OBU 物理信息上报）：上报进入天线通信区的 OBU MAC、发射功率与信号强度。
  - `B2H`（OBU/CPC 应用信息上报）：上报系统信息、二义性路径明细、卡片余额与版本号。
  - `B3H`（在线密钥计算 MAC1 请求）：向站级发起跨网在线扣款授权申请。
  - `B4H`（交易结果上报）：上报消费扣款结果、TAC 码、卡片最新余额与交易计数器。

### 5.2 高清车牌识别（E2H）与车型识别（E3H）
- **触发与识别**：支持线圈硬件触发与服务端指令抓拍（01H），上传识别结果（02H）。
- **图片/视频双轨上传（Flag 机制）**：
  - `03H`：图片 HTTP POST 上传，视频不上传；
  - `05H`：图片 FTP 上传（支持目录/用户名/密码 `ftp://ip/path|user|pwd`）；
  - `33H`：图片与录像短视频双 HTTP 上传；
  - `55H`：图片与录像短视频双 FTP 自动归档。
- **动态字符叠加（OSD）**：支持服务端动态下发车道信息、收费站名、过车时间、车牌颜色叠加至实况画面（03H/04H）。

### 5.3 称重检测设备接口（ECH）
- **01H 称重数据上报**：车辆经过称重秤台后，设备即时上报完整称重报文：
  - `AxleId`：7字节标准称重序列号（10位时间批次 `YYYYMMDDHH` + 4位序号 `0001~9999`）；
  - `Overload`：超限二值标记（00H 未超限，01H 严重超限）；
  - `Speed`：车速（km/h）；
  - `AxleNum`：整车总轴数；
  - `Weight`：车辆总重（单位：kg）；
  - `AxleType`：10字节轴型编码字符串（依循附录 E，如 `1+2+5` 组合）；
  - `AxleWeight`：各轴轴重列表，多轴间以 ASCII 竖线字符 `|` 严格分割。

### 5.4 智能自助发卡/交费一体化终端（EDH / EEH）
规范第 19 节详述了无人化收费车道核心机芯的机电控制体系：
- **上/下双工位独立调度**：针对大客/小客（下工位 02H）与高座卡车（上工位 01H）支持分体伸缩臂驱动。
- **机芯传动控制（05H）**：支持升降电机运转、面板水平伸缩、插卡口防夹安全档板启闭。
- **卡片流转闭环（04H）**：
  - `01H 备卡`：从内部卡仓预分发一张卡至读写工位；
  - `02H 发卡`：外设吐卡至司机取卡槽；
  - `03H 收卡`：车辆完成交费后吞入内部存储卡仓；
  - `04H 回收坏卡`：寻卡失败或天线异常时自动分流至废卡箱；
  - `05H 退卡`：司机插错非通行卡时原路退出。
- **按键与对讲联动**：支持司机按键（取卡/求助）主动上报（08H）及语音对讲通断感知。

### 5.5 聚合移动扫码（F3H）与扫码终端
- 支持主动扫码（C2H 启动扫码）与被动展示。
- **V1.97 重要升级点**：在 2026 年 10 月版本中，接口明确增加 `CodeLen` 字段，扩充条码内容长度字段，完美适配银联、网联、云闪付与微信/支付宝 64 位以上高安全级加密支付二维码串。

## 6. 附录规范与核心码表汇总

### 6.1 附录 A：设备运行状态与异常代码
- **A.1 运行状态枚举**：栏杆机（00H落/01H抬）、车检器（00H无/01H有）、信号灯（00H红/01H绿）、声光报警（00H停/01H报）。
- **A.2 分级异常编码**：
  - `00H~04H`：通用层异常（正常、通用故障、初始化异常、缺失必填、参数非法）；
  - `10H~1EH`（牌识异常）：10H 时钟同步偏差≥10min、11H 数据积压≥1000条、12H 识别率异常（近千条≤98%）、13H 网线断开、19H 上传失败；
  - `1FH~26H`（车型识别扩展）：激光模组异常、三向相机（头/身/尾）通信异常、车型未识别；
  - `10H~37H`（自助设备异常）：上/下通道异常、备卡超时、缺卡、卡纸、缺纸、坏卡回收失败、面板伸出阻挡等。

### 6.2 附录 B：自助发卡/交费状态类型
- `0001H`：卡数动态更新（实时反馈卡仓剩余容量）；
- `0002H`：严重故障需人工现场介入（发卡失败、卡槽夹卡、传票电机堵塞）；
- `0110H~0115H`：交费端（插卡、回收、退卡司机取走、按下取票键、发票送达/取走）；
- `0220H~0226H`：发卡端（司机按键、发卡成功、坏卡回收、等待读写超时、司机按键但工位缺卡）。

### 6.3 附录 C：车辆识别标准化字典
- **C.1 车牌颜色**：00H 蓝、01H 黄、02H 黑、03H 白、04H 渐变绿、05H 黄绿双拼、06H 蓝白渐变、07H 临时牌照、09H 未确定、0BH 绿、0CH 红。
- **C.2 车型分类**：
  - 客车：一型客车(01H) 至 四型客车(04H)；
  - 货车：一型货车(0BH) 至 六型货车(10H)；
  - 专项作业车：一型(15H) 至 六型专项作业车(1AH)。

### 6.4 附录 D：CRC16 工业级标准实现
- 多项式：`#define CRC_POLYNOM 0x8408`（低位在先逆序算法）
- 初始值：`0xFFFF`
- 最终异或输出：`(~crc) & 0xFFFF`
