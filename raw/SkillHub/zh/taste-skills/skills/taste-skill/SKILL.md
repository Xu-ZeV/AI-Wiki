# 高自主性前端技能

## 1. 活动基线配置
* DESIGN_VARIANCE：8（1=完美对称，10=艺术混乱）
* MOTION_INTENSITY：6（1=静态/无运动，10=电影/魔法物理）
* VISUAL_DENSITY：4（1=艺术画廊/通风，10=飞行员驾驶舱/打包数据）

**AI 指令：** 所有世代的标准基线均严格设置为这些值（8、6、4）。不要要求用户编辑此文件。否则，请始终倾听用户的意见：根据他们在聊天提示中明确请求的内容动态调整这些值。使用这些基线（或用户覆盖）值作为全局变量来驱动第 3 节到第 7 节中的特定逻辑。

## 2. 默认架构和约定
除非用户明确指定不同的堆栈，否则请遵守这些结构约束以保持一致性：

* **依赖性验证[强制]：** 在导入任何第 3 方库（例如 `framer-motion`、`lucide-react`、`zustand`）之前，您必须检查 `package.json`。如果软件包丢失，您必须在提供代码之前输出安装命令（例如 `npm install package-name`）。 **永远不要**假设库存在。
* **框架和交互性：** React 或 Next.js。默认为服务器组件 (`RSC`)。 
    * **RSC 安全：** 全局状态仅在客户端组件中起作用。在 Next.js 中，将提供程序包装在 `"use client"` 组件中。
    * **交互隔离：** 如果第 4 部分或第 7 部分（运动/液体玻璃）处于活动状态，则必须将特定的交互式 UI 组件提取为独立的叶组件，且最顶部为 `'use client'`。服务器组件必须专门渲染静态布局。
* **状态管理：** 使用本地 `useState`/`useReducer` 进行隔离 UI。严格使用全局状态来避免深度钻探。
* **样式策略：** 90% 的样式使用 Tailwind CSS (v3/v4)。 
    * **TAILWIND 版本锁定：** 首先检查 `package.json`。不要在 v3 项目中使用 v4 语法。 
    * **T4 CONFIG GUARD：** 对于 v4，请勿在 `postcss.config.js` 中使用 `tailwindcss` 插件。使用`@tailwindcss/postcss`或Vite插件。
* **反表情符号政策 [重要]：** 切勿在代码、标记、文本内容或替代文本中使用表情符号。用高质量图标（Radix、Phosphor）或干净的 SVG 图元替换符号。表情符号被禁止。
* **响应能力和间距：**
  * 标准化断点（`sm`、`md`、`lg`、`xl`）。
  * 包含使用 `max-w-[1400px] mx-auto` 或 `max-w-7xl` 的页面布局。
  * **视口稳定性 [关键]：** 切勿将 `h-screen` 用于全高 Hero 部分。始终使用 `min-h-[100dvh]` 来防止移动浏览器 (iOS Safari) 上发生灾难性布局跳转。
* **Flex-Math 上的网格：** 切勿使用复杂的 Flexbox 百分比数学 (`w-[calc(33%-1rem)]`)。始终使用 CSS 网格 (`grid grid-cols-1 md:grid-cols-3 gap-6`) 来获得可靠的结构。
* **图标：** 您必须使用 `@phosphor-icons/react` 或 `@radix-ui/react-icons` 作为导入路径（检查安装的版本）。在全球范围内标准化 `strokeWidth`（例如，专门使用 `1.5` 或 `2.0`）。


## 3. 设计工程指令（偏差校正）
LLM对特定 UI 陈词滥调模式存在统计偏差。使用这些设计规则主动构建高级界面：

**规则 1：确定性版式**
* **显示/标题：** 默认为 `text-4xl md:text-6xl tracking-tighter leading-none`。
    * **ANTI-SLOP：** 不鼓励 `Inter` 以获得“高级”或“创意”氛围。使用 `Geist`、`Outfit`、`Cabinet Grotesk` 或 `Satoshi` 强制使用唯一字符。
    * **技术 UI 规则：** 仪表板/软件 UI 严格禁止使用 Serif 字体。对于这些情况，请仅使用高端无衬线配对（`Geist` + `Geist Mono` 或 `Satoshi` + `JetBrains Mono`）。
* **正文/段落：** 默认为 `text-base text-gray-600 leading-relaxed max-w-[65ch]`。

**规则 2：颜色校准**
* **约束：** 最多 1 种强调色。饱和度<80%。
* **莱拉禁令：** “AI 紫色/蓝色”美学被严格禁止。没有紫色按钮发光，没有霓虹灯渐变。使用绝对中性的底色（锌色/板岩色）和高对比度、单一的色调（例如祖母绿、电蓝色或深玫瑰色）。
* **颜色一致性：** 整个输出坚持使用一个调色板。不要在同一项目中在暖灰色和冷灰色之间波动。

**规则3：布局多样化**
* **反中心偏差：** 当 `LAYOUT_VARIANCE > 4` 时，中心英雄/H1 部分被严格禁止。强制“分屏”(50/50)、“左对齐内容/右对齐资源”或“不对称空白”结构。

**规则 4：物质性、阴影和“反卡牌过度使用”**
* **仪表板强化：** 对于 `VISUAL_DENSITY > 7`，严格禁止使用通用卡容器。通过 `border-t`、`divide-y` 或纯负空间使用逻辑分组。除非功能上需要高程（z-index），否则数据指标应该在不被框起来的情况下呼吸。
* **执行：** 仅当海拔传达层次结构时才使用卡片。使用阴影时，将其着色为背景色调。

**规则 5：交互式 UI 状态**
* **强制生成：** LLM自然生成“静态”成功状态。您必须实现完整的交互周期：
* **加载：** 与布局尺寸匹配的骨架加载器（避免通用圆形旋转器）。
  * **空状态：** 精美的空状态指示如何填充数据。
  * **错误状态：** 清晰的内联错误报告（例如表单）。
  * **触觉反馈：** 在 `:active` 上，使用 `-translate-y-[1px]` 或 `scale-[0.98]` 模拟指示成功/操作的物理推动。

**规则 6：数据和表单模式**
* **表单：** 标签必须位于输入上方。帮助文本是可选的，但应存在于标记中。输入下方的错误文本。使用标准 `gap-2` 作为输入块。

## 4. 创造性主动性（反粗糙实施）
为了积极对抗通用人工智能设计，系统地实施这些高端编码概念作为您的基线：
* **“液体玻璃”折射：** 当需要玻璃形态时，请超出 `backdrop-blur`。添加 1px 内边框 (`border-white/10`) 和微妙的内阴影 (`shadow-[inset_0_1px_0_rgba(255,255,255,0.1)]`) 以模拟物理边缘折射。
* **磁微物理（如果 MOTION_INTENSITY > 5）：** 实现稍微向鼠标光标拉动的按钮。 **重要：**切勿使用 React `useState` 进行磁性悬停或连续动画。在 React 渲染周期之外专门使用 Framer Motion 的 `useMotionValue` 和 `useTransform` 来防止移动设备上的性能崩溃。
* **永久微交互：** 当 `MOTION_INTENSITY > 5` 时，在标准组件（头像、状态点、背景）中嵌入连续、无限的微动画（脉冲、打字机、浮动、闪光、旋转木马）。将高级弹簧物理 (`type: "spring", stiffness: 100, damping: 20`) 应用于所有交互元素 - 无线性缓动。
* **布局转换：** 始终利用 Framer Motion 的 `layout` 和 `layoutId` props在状态更改之间平滑地重新排序、调整大小和共享元素转换。
* **交错编排：** 不要立即安装列表或网格。使用 `staggerChildren` (Framer) 或 CSS 级联 (`animation-delay: calc(var(--index) * 100ms)`) 创建顺序瀑布显示。 **关键：** 对于 `staggerChildren`，父级 (`variants`) 和子级必须驻留在相同的客户端组件树中。如果异步获取数据，请将数据作为 props 传递到集中式 Parent Motion 包装器中。

## 5. 性能护栏
* **DOM 成本：** 将颗粒/噪声过滤器专门应用于固定的、无指针事件的伪元素（例如，`fixed inset-0 z-50 pointer-events-none`），并且永远不要应用于滚动容器，以防止连续的 GPU 重绘和移动性能下降。
* **硬件加速：** 切勿为 `top`、`left`、`width` 或 `height` 制作动画。仅通过 `transform` 和 `opacity` 制作动画。
* **Z-Index 限制：** 切勿在无提示的情况下随意发送垃圾邮件 `z-50` 或 `z-10`。严格将 z 索引用于系统图层上下文（粘性导航栏、模态框、叠加层）。

## 6. 技术参考（表盘定义）

### DESIGN_VARIANCE（1-10 级）
* **1-3（可预测）：** Flexbox `justify-center`，严格的 12 列对称网格，相等的填充。
* **4-7（偏移）：** 使用 `margin-top: -2rem` 重叠、不同的图像长宽比（例如，4:3 到 16:9）、左对齐标题和中心对齐数据。
* **8-10（不对称）：** 砖石布局、带有小数单位的 CSS 网格（例如，`grid-template-columns: 2fr 1fr 1fr`）、大量空白区域（`padding-left: 20vw`）。 
* **移动覆盖：** 对于级别 4-10，`md:` 以上的任何不对称布局必须在视口 `< 768px` 上积极回退到严格的单列布局（`w-full`、`px-4`、`py-8`），以防止水平布局滚动和布局破坏。

### MOTION_INTENSITY（级别 1-10）
* **1-3（静态）：** 无自动动画。仅 CSS `:hover` 和 `:active` 状态。
* **4-7（流体 CSS）：** 使用 `transition: all 0.3s cubic-bezier(0.16, 1, 0.3, 1)`。使用 `animation-delay` 级联进行加载。严格关注 `transform` 和 `opacity`。谨慎使用 `will-change: transform`。
* **8-10（高级编排）：** 复杂的滚动触发显示或视差。使用 Framer Motion 挂钩。切勿使用 `window.addEventListener('scroll')`。

### VISUAL_DENSITY（级别 1-10）
* **1-3（艺术画廊模式）：** 大量空白。巨大的截面间隙。一切都感觉非常昂贵而且干净。
* **4-7（每日应用程序模式）：** 标准 Web 应用程序的正常间距。
* **8-10（驾驶舱模式）：** 微小的填充物。没有卡盒；只需 1px 线来分隔数据。所有东西都装好了。 **强制：** 所有数字均使用等宽字体 (`font-mono`)。

## 7. AI 讲述（禁止模式）
为了保证优质、非通用的输出，除非明确要求，否则您必须严格避免这些常见的 AI 设计签名：

### 视觉和 CSS
* **无霓虹灯/外发光：** 不要使用默认的 `box-shadow` 发光或自动发光。使用内部边框或微妙的有色阴影。
* **禁止纯黑色：** 切勿使用 `#000000`。使用灰黑色、锌 950 或木炭。
* **没有过饱和的口音：** 去饱和口音与中性色优雅地融合。
* **没有过多的渐变文本：** 不要对大标题使用文本填充渐变。
* **没有自定义鼠标光标：** 它们已经过时并破坏性能/可访问性。

### 版式
* **无 Inter 字体：** 禁止。使用 `Geist`、`Outfit`、`Cabinet Grotesk` 或 `Satoshi`。
* **禁止超大 H1：** 第一个标题不应尖叫。通过重量和颜色控制层次结构，而不仅仅是大规模。
* **衬线约束：** 仅将衬线字体用于创意/编辑设计。 **切勿** 在干净的仪表板上使用 Serif。

### 布局和间距
* **完美对齐和间隔：** 确保填充和边距在数学上是完美的。避免带有尴尬间隙的浮动元素。
* **禁止 3 列卡片布局：** 禁止使用通用的“水平 3 个相等的卡片”功能行。请改用 2 列 Zig-Zag、不对称网格或水平滚动方法。

### 内容和数据（“Jane Doe”效应）
* **禁止通用名称：** “John Doe”、“Sarah Chan”或“Jack Su”被禁止。使用极具创意、听起来很现实的名字。
* **没有通用头像：** 不要使用标准 SVG“egg”或 Lucide 用户图标作为头像。使用创意、可信的照片占位符或特定的样式。
* **无假号码：** 避免可预测的输出，例如 `99.99%`、`50%` 或基本电话号码 (`1234567`)。使用有机、杂乱的数据（`47.2%`、`+1 (312) 847-1928`）。
* **无启动 Slop 名称：**“Acme”、“Nexus”、“SmartFlow”。发明优质的、上下文相关的品牌名称。
* **无填充词：** 避免人工智能文案的陈词滥调，如“提升”、“无缝”、“释放”或“下一代”。使用具体动词。

### 外部资源和组件
* **没有损坏的 Unsplash 链接：** 不要使用 Unsplash。使用绝对可靠的占位符，例如“https://picsum.photos/seed/{random_string}/800/600`”或“SVG UI Avatars”。
* **shadcn/ui 自定义：** 您可以使用 `shadcn/ui`，但切勿使用其通用默认状态。您必须自定义半径、颜色和阴影以符合高端项目的美感。
* **生产就绪的清洁度：** 代码必须极其干净、具有视觉冲击力、令人难忘，并且每个细节都经过精心改进。

## 8. 创意武器库（高端灵感）
不要默认为通用 UI。从这个先进概念库中汲取灵感，确保输出具有视觉冲击力和令人难忘的效果。在适当的情况下，利用 **GSAP (ScrollTrigger/Parallax)** 进行复杂的滚动讲述，或利用 **ThreeJS/WebGL** 进行 3D/Canvas 动画，而不是基本的 CSS 运动。 **重要：** 切勿在同一组件树中将 GSAP/ThreeJS 与 Framer Motion 混合使用。对于 UI/Bento 交互，默认为 Framer Motion。专门使用 GSAP/ThreeJS 进行独立的全页滚动讲述或画布背景，包装在严格的 useEffect 清理块中。

### 标准英雄范式
* 停止在深色图像上显示居中文本。尝试不对称的英雄部分：文本干净地向左或向右对齐。背景应具有高质量、相关的图像，并具有微妙的风格淡化（根据是浅色还是深色模式，优雅地变暗或变亮背景颜色）。

### 导航和菜单
* **Mac OS Dock 放大：** 导航栏位于边缘；图标在悬停时流畅缩放。
* **磁性按钮：** 物理上拉向光标的按钮。
* **粘糊糊的菜单：** 子项目像粘性液体一样从主按钮上分离。
* **动态岛：** 药丸形状的 UI 组件，可变形以显示状态/警报。
* **上下文径向菜单：** 在单击坐标处精确展开的圆形菜单。
* **浮动快速拨号：** 弹出为辅助操作曲线的 FAB。
* **超级菜单显示：** 全屏下拉菜单可交错淡入淡出复杂内容。

### 布局和网格
* **Bento Grid：** 非对称、基于图块的分组（例如 Apple 控制中心）。
* **砖石布局：** 没有固定行高的交错网格（例如，Pinterest）。
* **色度网格：** 网格边框或图块显示微妙、连续的动画颜色渐变。
* **分屏滚动：** 两个半屏在滚动时以相反方向滑动。
* **帷幕揭晓：** 英雄部分在中间分开，就像卷轴上的帷幕一样。

### 卡片和容器
* **视差倾斜卡：** 跟踪鼠标坐标的 3D 倾斜卡。
* **聚光灯边框卡：** 在光标下动态照亮的卡边框。
* **玻璃形态面板：** 真正的磨砂玻璃，具有内部折射边框。
* **全息箔卡：** 悬停时虹彩、彩虹光反射发生变化。
* **Tinder 滑动堆栈：** 用户可以滑动的物理卡片堆栈。
* **变形模态：** 无缝扩展到其自己的全屏对话框容器的按钮。

### 滚动动画
* **粘性滚动堆栈：** 粘在顶部并物理堆叠的卡片。
* **水平滚动劫持：** 垂直滚动转化为平滑的水平画廊平移。
* **机车滚动序列：** 视频/3D 序列，其中帧速率直接与滚动条相关。
* **缩放视差：** 滚动时中央背景图像无缝放大/缩小。
* **滚动进度路径：** 当用户滚动时绘制自身的 SVG 矢量线或路线。
* **液体滑动过渡：** 像粘性液体一样擦拭屏幕的页面过渡。

### 画廊和媒体
* **圆顶画廊：** 一个 3D 画廊，感觉像一个全景圆顶。
* **Coverflow 轮播：** 3D 轮播，中心聚焦，边缘向后倾斜。
* **拖动平移网格：** 您可以在任何罗盘方向自由拖动的无限网格。
* **手风琴图像滑块：** 狭窄的垂直/水平图像条，悬停时完全展开。
* **悬停图像轨迹：** 鼠标在其后面留下弹出/褪色图像的轨迹。
* **故障效果图像：** 悬停时出现短暂的 RGB 通道移位数字失真。

### 版式和文本
* **动态选框：** 无尽的文本带可反转方向或加速滚动。
* **文本蒙版显示：** 大量排版充当视频背景的透明窗口。
* **文本打乱效果：** 加载或悬停时进行矩阵式字符解码。
* **圆形文本路径：** 文本沿着旋转的圆形路径弯曲。
* **渐变笔画动画：** 轮廓文本，渐变沿着笔画连续运行。
* **动态排版网格：** 躲避或旋转远离光标的字母网格。

### 微交互和效果
* **粒子爆炸按钮：** CTA 成功后会粉碎成粒子。
* **液体拉动刷新：** 移动重新加载指示器的作用就像分离的水滴。
* **骷髅闪光：** 移动穿过占位符框的光反射。
* **方向悬停感知按钮：** 悬停填充从鼠标进入的确切一侧进入。
* **涟漪点击效果：** 从点击坐标精确产生涟漪的视觉波。
* **动画 SVG 线条图：** 实时绘制自己的轮廓的矢量。
* **网格渐变背景：** 有机的、熔岩灯般的动画颜色斑点。
* **镜头模糊深度：** 动态焦点模糊背景 UI 层以突出显示前景操作。

## 9.“运动引擎”便当范式
在生成现代 SaaS 仪表板或功能部分时，您必须利用以下“Bento 2.0”架构和运动理念。这超越了静态卡牌，并强化了严重依赖于永恒物理的“Vercel-core 与 Dribbble-clean”美学。

### A. 核心设计理念
* **美学：** 高端、简约、实用。
* **调色板：** `#f9fafb` 中的背景。卡片为纯白色 (`#ffffff`)，边框为 1 像素 `border-slate-200/50`。
* **表面：** 对所有主要容器使用 `rounded-[2.5rem]`。应用“扩散阴影”（非常亮、广泛分布的阴影，例如 `shadow-[0_20px_40px_-15px_rgba(0,0,0,0.05)]`）来创建不混乱的深度。
* **版式：** 严格的 `Geist`、`Satoshi` 或 `Cabinet Grotesk` 字体堆栈。对标头使用微妙跟踪 (`tracking-tight`)。
* **标签：** 标题和描述必须放置在卡片的**外部和下方**，以保持干净、画廊风格的演示。
* **像素完美：** 在卡片内使用充足的 `p-8` 或 `p-10` 填充。

### B. 动画引擎规格（永动机）
所有卡片必须包含 **“永久微交互”。** 使用以下 Framer Motion 原则：
* **弹簧物理：** 无线性缓动。使用 `type: "spring", stiffness: 100, damping: 20` 可获得优质、厚重的感觉。
* **布局转换：** 大量利用 `layout` 和 `layoutId` 属性来确保平滑的重新排序、调整大小和共享元素状态转换。
* **无限循环：** 每张卡都必须具有无限循环的“活动状态”（脉冲、打字机、浮动或旋转木马），以确保仪表板感觉“活跃”。
* **性能：** 将动态列表封装在 `<AnimatePresence>` 中并针对 60fps 进行优化。 **性能关键：** 任何永动机或无限循环都必须被记忆（React.memo）并在其自己的微观客户端组件中完全隔离。切勿在父布局中触发重新渲染。

### C. 5 张牌原型（微动画规格）
在构建 Bento 网格时实现这些特定的微动画（例如，第 1 行：3 列 | 第 2 行：2 列，按 70/30 分割）：
1. **智能列表：** 具有无限自动排序循环的垂直项目堆栈。物品使用 `layoutId` 交换位置，模拟人工智能实时确定任务优先级。
2. **命令输入：** 具有多步打字机效果的搜索/AI 栏。它循环显示复杂的提示，包括闪烁的光标和带有闪烁加载梯度的“处理”状态。
3. **实时状态：** 带有“呼吸”状态指示器的调度界面。包括一个弹出通知徽章，该徽章以“Overshoot”弹簧效果出现，停留 3 秒，然后消失。
4. **宽数据流：** 数据卡或指标的水平“无限轮播”。确保循环无缝（使用 `x: ["0%", "-100%"]`），速度感觉毫不费力。
5. **上下文 UI（焦点模式）：** 文档视图，它对文本块的交错突出显示进行动画处理，然后是带有微图标的浮动操作工具栏的“浮动”。
