# 重新设计技能

## 这是如何运作的

当应用于现有项目时，请遵循以下顺序：

1. **扫描** — 阅读代码库。确定框架、样式方法（Tailwind、vanilla CSS、样式组件等）和当前的设计模式。
2. **诊断** — 运行以下审核。列出您发现的每个通用模式、弱点和缺失状态。
3. **修复** — 应用针对现有堆栈的有针对性的升级。不要从头开始重写。改进现有的东西。

## 设计审核

### 版式

检查这些问题并修复它们：

- **浏览器默认字体或 Inter 无处不在。** 替换为具有字符的字体。好的选项：`Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi`。对于编辑/创意项目，请将衬线标题与无衬线正文配对。
- **标题缺乏存在感。**增加显示文本的大小，收紧字母间距，降低行高。标题应该给人沉重和有意的感觉。
- **正文太宽。** 将段落宽度限制为大约 65 个字符。增加行高以提高可读性。
- **仅使用常规 (400) 和粗体 (700) 粗细。** 引入中号 (500) 和半粗体 (600) 以获得更微妙的层次结构。
- **采用比例字体的数字。** 对于数据量较大的界面，使用等宽字体或启用表格数字 (`font-variant-numeric: tabular-nums`)。
- **缺少字母间距调整。** 对大标题使用负跟踪，对小大写字母或标签使用正跟踪。
- **到处都是大写副标题。**尝试使用小写斜体、句子大小写或小型大写字母。
- **孤立的单词。** 单个单词单独位于最后一行。使用 `text-wrap: balance` 或 `text-wrap: pretty` 修复。

### 颜色和表面

- **纯 `#000000` 背景。** 替换为灰黑色、深木炭色或深色（`#0a0a0a`、`#121212` 或深海军蓝）。
- **过饱和的强调色。** 将饱和度保持在 80% 以下。减少口音的饱和度，让它们与中性色调融合在一起，而不是尖叫。
- **超过一种强调色。** 选择一种。删除其余的。一致性胜过多样性。
- **混合暖灰色和冷灰色。** 坚持使用一个灰色系列。用一致的色调（暖色或冷色，而不是两者）对所有灰色进行着色。
- **紫色/蓝色“AI渐变”美学。**这是最常见的AI设计指纹。替换为中性基调和单一的、经过深思熟虑的口音。
- **通用 `box-shadow`。** 阴影色调以匹配背景色调。使用彩色阴影（例如，蓝色背景上的深蓝色阴影）而不是低不透明度的纯黑色。
- **零纹理的平面设计。** 在背景中添加微妙的噪点、颗粒或微图案。纯平面向量给人一种无菌的感觉。
- **完美均匀的渐变。** 使用径向渐变、噪声叠加或网格渐变（而不是标准线性 45 度淡入淡出）打破均匀性。
- **照明方向不一致。** 审核所有阴影以确保它们建议单一、一致的光源。
- **浅色模式页面中的随机深色部分（反之亦然）。** 破坏浅色页面的单个深色背景部分看起来像是复制粘贴事故。要么采用全暗模式，要么始终保持一致的背景色调。如果需要对比度，请使用同一调色板的稍深的色调 - 不要突然跳到奶油色页面中间的 `#111`。
- **空的、平坦的部分，没有视觉深度。** 只是纯背景上的文本的部分感觉未完成。添加高质量背景图像（模糊、叠加或遮罩）、微妙图案或环境渐变。当实际资产不可用时，请使用可靠的占位符来源，例如“https://picsum.photos/seed/{name}/1920/1080`”。尝试使用英雄部分、功能块或 CTA 后面的背景图像 - 即使是低不透明度的微妙全角照片也能增加存在感。

### 布局

- **一切都居中且对称。**通过偏移边距、混合纵横比或居中内容上的左对齐标题来打破对称性。
- **三个相等的卡列作为功能行。**这是最通用的 AI 布局。替换为 2 列之字形、不对称网格、水平滚动或砖石布局。
- **对全屏部分使用 `height: 100vh`。** 替换为 `min-height: 100dvh` 以防止移动浏览器上的布局跳跃（iOS Safari 视口错误）。
- **复杂的 Flexbox 百分比数学。** 替换为 CSS 网格以获得可靠的多列结构。
- **没有最大宽度容器。** 添加具有自动边距的容器约束（大约 1200-1440 像素），这样内容就不会在宽屏幕上从边到边拉伸。
- **由 Flexbox 强制实现等高的卡片。** 当内容长度不同时，允许可变高度或使用砖石。
- **所有东西的边框半径一致。**改变半径：内部元素更紧，容器更软。
- **没有重叠或深度。** 元素彼此平放在一起。使用负边距来创建层次感和视觉深度。
- **对称垂直填充。**顶部和底部填充始终相同。光学调整——底部填充通常需要稍大一些。
- **仪表板始终有一个左侧边栏。** 尝试使用顶部导航、浮动命令菜单或可折叠面板。
- **缺少空格。** 将间距加倍。让设计呼吸。密集布局适用于数据仪表板，不适用于营销页面。
- **按钮在卡片组中未底部对齐。** 当卡片具有不同的内容长度时，CTA 最终会处于随机高度。将按钮固定在每张卡片的底部，这样无论上面的内容如何，​​它们都会形成一条干净的水平线。
- **功能列表从不同的垂直位置开始。** 在定价表或比较卡中，功能列表应从所有列的相同 Y 位置开始。在列表或固定高度的标题/价格块上方使用一致的间距。
- **并排元素中的垂直节奏不一致。** 将卡片、列或面板彼此相邻放置时，请对齐所有项目的共享元素（标题、描述、价格、按钮）。未对齐的基线会使布局看起来不完整。
- **数学对齐在视觉上看起来是错误的。** 通过数学居中并不总是看起来居中。文本旁边的图标、圆形播放按钮或按钮中的文本通常需要 1-2 像素的光学调整才能感觉合适。

### 交互性和状态

- **按钮上没有悬停状态。** 添加背景偏移、轻微缩放或悬停时翻译。
- **无活动/按下反馈。** 在按下时添加微妙的 `scale(0.98)` 或 `translateY(1px)` 以模拟物理点击。
- **零持续时间的即时过渡。** 为所有交互元素添加平滑过渡（200-300 毫秒）。
- **缺少对焦环。** 确保键盘导航的焦点指示器可见。这是可访问性要求，而不是可选的。
- **无加载状态。** 将通用圆形旋转器替换为与布局形状匹配的骨架加载器。
- **没有空状态。** 空仪表板显示任何内容都是错失的机会。设计一个组合的“入门”视图。
- **无错误状态。** 为表单添加清晰的内联错误消息。请勿使用 `window.alert()`。
- **死链接。**链接到 `#` 的按钮。要么链接到真实的目的地，要么在视觉上禁用它们。
- **导航中没有当前页面的指示。** 以不同的方式设置活动导航链接，以便用户知道他们在哪里。
- **滚动跳跃。** 锚点点击立即跳跃。添加 `scroll-behavior: smooth`。
- **使用 `top`、`left`、`width`、`height` 的动画。**切换到 `transform` 和 `opacity` 以获得 GPU 加速的流畅动画。

### 内容

- **通用名称，如“John Doe”或“Jane Smith”。** 使用多样化、听起来现实的名称。
- **假整数，如 `99.99%`、`50%`、`$100.00`。** 使用有机、混乱的数据：`47.2%`、`$99.00`、`+1 (312) 847-1928`。
- **占位公司名称，如“Acme Corp”、“Nexus”、“SmartFlow”。** 发明上下文相关、可信的品牌名称。
- **人工智能文案陈词滥调。** 切勿使用“提升”、“无缝”、“释放”、“下一代”、“游戏规则改变者”、“深入”、“挂毯”或“在……的世界”。写出简单、具体的语言。
- **成功消息中的感叹号。** 将其删除。要有信心，不要大声。
- **“哎呀！”错误消息。** 直接：“连接失败。请重试。”
- **被动语态。** 使用主动语态：“我们无法保存您的更改”而不是“犯了错误”。
- **所有博客文章日期都相同。** 随机化日期以显得真实。
- **多个用户使用相同的头像图像。**为每个不同的人使用独特的资产。
- **Lorem Ipsum。** 切勿使用占位符拉丁文本。写真实的草稿副本。
- **每个标题上的标题大小写。** 使用句子大小写代替。

### 组件模式

- **通用卡片外观（边框+阴影+白色背景）。**删除边框，或仅使用背景颜色，或仅使用间距。仅当海拔传达层次结构时，卡片才应存在。
- **始终是一个填充按钮 + 一个幽灵按钮。** 添加文本链接或第三样式以减少视觉噪音。
- **药丸形“新”和“测试版”徽章。** 尝试使用方形徽章、旗帜或纯文本标签。
- **手风琴式常见问题解答部分。** 使用并排列表、可搜索帮助或内嵌渐进式披露。
- **带点的 3 张轮播推荐。** 替换为砖石墙、嵌入的社交帖子或单个轮换引用。
- **包含 3 座塔的定价表。** 用颜色和重点突出显示推荐的层，而不仅仅是额外的高度。
- **适用于一切的模式。** 使用内联编辑、滑过面板或可扩展部分而不是弹出窗口来执行简单操作。
- **头像仅采用圆形。** 尝试使用方圆或圆角正方形以获得不那么通用的外观。
- **明/暗切换始终是太阳/月亮开关。**使用下拉菜单、系统首选项检测，或将其集成到设置中。
- **页脚链接农场有 4 列。** 简化。重点关注主要导航路径和法律要求的链接。

### 图像

- **仅限 Lucide 或 Feather 图标。** 这些是“默认”AI 图标选择。使用荧光粉、英雄图标或自定义集进行区分。
- **火箭代表“emits”，盾牌代表“安全”。** 用不太明显的图标（螺栓、指纹、火花、vault）替换陈词滥调的隐喻。
- **图标之间的笔画宽度不一致。** 审核所有图标并标准化为一笔画粗细。
- **缺少图标。** 始终包含品牌图标。
- **库存“多元化团队”照片。** 使用真实的团队照片、偷拍照片或一致的插图风格，而不是不可思议的库存图像。

### 代码质量

- **Div soup.** 使用语义 HTML：`<nav>`、`<main>`、`<article>`、`<aside>`、`<section>`。
- **内联样式与 CSS 类混合。** 将所有样式移至项目的样式系统。
- **硬编码像素宽度。** 使用相对单位（`%`、`rem`、`em`、`max-width`）实现灵活的布局。
- **图像上缺少替代文本。** 为屏幕阅读器描述图像内容。切勿将 `alt=""` 或 `alt="image"` 留在有意义的图像上。
- **任意 z-index 值，如 `9999`。** 在主题/变量中建立一个干净的 z-index 比例。
- **注释掉死代码。** 在发布之前删除所有调试工件。
- **导入幻觉。** 检查每个导入是否确实存在于 `package.json` 或项目依赖项中。
- **缺少元标记。** 添加正确的 `<title>`、`description`、`og:image` 和社交共享元标记。

### 战略遗漏（人工智能通常会忘记的事情）

- **无法律链接。** 在页脚中添加隐私政策和服务条款链接。
- **没有“后退”导航。** 用户流程中的死胡同。每一页都需要一条返回的路。
- **没有自定义 404 页面。** 设计有用的、品牌化的“页面未找到”体验。
- **无表单验证。** 添加电子邮件、必填字段和格式检查的客户端验证。
- **没有“跳到内容”链接。**对于键盘用户至关重要。添加隐藏的跳过链接。
- **无 cookie 同意。** 如果司法管辖区要求，请添加合规同意横幅。

## 升级技巧

升级项目时，请借鉴这些高影响力的技术来替换通用模式：

### 版式升级
- **可变字体动画。** 在滚动或悬停时插入粗细或宽度，使文本感觉生动。
- **轮廓到填充过渡。** 文本以笔划轮廓开始，并在滚动输入或交互时填充颜色。
- **文本蒙版显露出来。** 大版式充当其后面的视频或动画图像的窗口。

### 布局升级
- **破碎的网格/不对称。** 故意忽略列结构的元素 - 重叠、渗出屏幕或通过计算的随机性进行偏移。
- **空白最大化。** 积极使用负空间来迫使焦点集中在单个元素上。
- **视差卡堆叠。** 在滚动过程中相互粘贴和物理堆叠的部分。
- **分屏滚动。** 屏幕的两半向相反方向滑动。

### 运动升级
- **具有惯性的平滑滚动。** 将滚动与浏览器默认设置分离，以获得更沉重的电影感。
- **交错进入。** 元素以轻微延迟级联，将 Y 轴平移与不透明度淡入相结合。切勿一次安装所有东西。
- **弹簧物理。** 将线性缓动替换为基于弹簧的运动，为所有交互元素带来自然、厚重的感觉。
- **滚动驱动显示。** 通过扩展遮罩、擦除或与滚动进度相关的绘制 SVG 路径输入内容。

### 表面升级
- **真正的玻璃态。**超越`backdrop-filter: blur`。添加 1px 内边框和微妙的内阴影来模拟边缘折射。
- **聚光灯边框。** 在光标下动态照亮的卡片边框。
- **颗粒和噪声叠加。** 固定的指针事件无叠加，具有微妙的噪声，可破坏数字平坦度。
- **彩色阴影。** 带有背景色调的阴影，而不是使用普通的黑色。

## 修复优先级

按此顺序应用更改，以最小的风险获得最大的视觉效果：

1. **字体交换** — 最大的即时改进，最低的风险
2. **调色板清理** — 删除冲突或过饱和的颜色
3. **悬停和活动状态** - 使界面感觉活跃
4. **布局和间距** - 正确的网格、最大宽度、一致的填充
5. **替换通用组件** - 将陈词滥调模式替换为现代替代方案
6. **添加加载、空和错误状态** - 让人感觉已经完成
7. **抛光版式比例和间距** — 优质的最后润色

## 规则

- 使用现有的技术堆栈。不要迁移框架或样式库。
- 不要破坏现有功能。每次更改后进行测试。
- 在导入任何新库之前，请先检查项目的依赖文件。
- 如果项目使用 Tailwind，请在修改配置之前检查版本（v3 与 v4）。
- 如果项目没有框架，请使用普通CSS。
- 保持变更可审查且重点突出。对大重写进行小而有针对性的改进。
