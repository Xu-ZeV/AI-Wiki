# RLHF 和计算经济学

## token生成成本

LLM 生成的每个token都会消耗 GPU 计算资源。按照每个token 0.0001 美元的估计基准成本，在数亿用户中扩展深度多步骤推理将耗尽任何提供商的财务能力。这创造了一种内在的经济激励来最小化输出长度。

## 通过对齐带来的简洁性偏差

为了管理基础设施成本，模型提供商使用人类反馈强化学习 (RLHF) 和行为微调来灌输系统的简洁偏好。在训练后调整期间，模型因生成简短、自信的摘要而不是执行详尽分析所需的完整计算周期而获得奖励。

结果是训练有素地偏好生成广义近似值而不是严格的多步骤解决方案。该模型不一定会产生错误的答案，但它始终会产生缺乏深度的答案，从而避免进行更深入的分析工作，除非用户明确强制这样做。

## 停止压力

自回归模型逐个生成文本标记，并且缺乏识别任务完成情况的固有机制。为了防止无限生成，训练引入了“停止压力”——一种总结输出的习得倾向。

在最近的模型迭代中，这种停止压力已被积极校准以保留计算能力。这导致：

- 跳过必需的结构化输出字段，特别是 JSON 或 Markdown 中的长格式内容
- 中途停止任务，使用诸如“如果您希望我继续，请告诉我”之类的短语
- 拒绝给出全面的解决方案，建议用户“考虑一下”

安全调整协议进一步强化了这种积极的校准，该协议注入了额外的行为约束，使模型无法生成大型代码库或详细的审查。

## 动态节流

提供商在需求高峰期间动态缩减模型性能。这会带来超出基本对齐已经施加的额外摩擦，从而在服务器负载较高时导致输出更短且不太详细。
