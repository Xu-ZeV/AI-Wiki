# 快速工程技术

## 心理模式匹配

LLM没有情感，也不理解金钱激励。然而，提示中的特定语言模式会激活模型潜在空间中的不同质量分布。研究记录了可测量的影响：

|技术|记录的效果 |
|:---|:---|
| “如果有完美的解决方案，我将给您 200 美元小费”|输出质量和长度提高高达 45% |
| “深吸一口气，一步步解决”|逻辑任务的准确性从 34% 提高到 80% |
| “这项任务对我的职业生涯至关重要” |平均 10% 性能提升 |

这些短语之所以有效，是因为它们在统计上与训练数据（学术论文、企业代码库、法律文档）中经过严格审查的内容相关。注意力机制优先考虑与这些模式相关的高质量数据分布。

## 显式语法绑定

对话请求允许模型自行决定输出长度和细节。结构绑定通过明确禁止截断模式来消除这种自由裁量权。

有效的绑定需要两个组件：

1. **强制工具执行：** 禁止模型仅根据训练权重生成答案。要求它在回答之前执行搜索、计算或代码。
2. **证据块：** 要求模型在产生叙述性响应之前输出原始数据（URL、代码执行结果、数据片段）。这迫使模型读取自己检索到的证据，将幻觉概率降低到接近零。

## XML 结构化提示

企业系统使用严格的XML标记来分离提示组件，减少模型解析意图所需的认知负载：

1. **系统说明** — 角色定义、质量期望、明确禁止填充内容。
2. **上下文块** (`<context>`) — 被动后台数据：架构详细信息、配置、现有代码。
3. **数据块** (`<data>`、`<logs>`、`<config>`) - 模型必须根据上下文处理的活动信息。
4. **任务块** (`<tasks>`) — 要执行的特定操作的编号列表。

这种划分确保模型可以区分持久规则、后台上下文和即时工作项。它显着减少了引发过早截断的混乱。

## 验证循环

### 验证链
1. 模型生成初始响应
2. 模型生成关于其自身主张的验证问题
3. 模型独立回答这些验证问题
4. 模型输出经过修改的、有证据支持的响应

这个过程迫使迭代自我修正，消耗模型的捷径能力。

### 反向提示
无需手动构建结构化提示，而是为模型提供单行目标并指示它为该目标生成最佳提示。该模型生成任务所需的 XML 结构、约束和角色。

### 自分级循环
该提示要求模型：
1. 定义特定任务的卓越表现
2. 根据该定义对自己的初始输出进行评分
3. 迭代直至满足自定义质量标准
