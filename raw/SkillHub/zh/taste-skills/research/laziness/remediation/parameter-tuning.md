# 参数调优

## 温度和 Top-p

自回归模型从应用于 logit 值的 softmax 函数生成的概率分布中选择每个下一个标记。当模型默认为简短输出时，与截断和摘要相关的标记已通过 RLHF 对齐分配了最高概率。

### 温度

调整温度参数会改变 softmax 函数在候选标记之间分配概率质量的方式。

- **低温（0.0 - 0.5）：** 放大高概率token和低概率token之间的差异。该模型变得高度确定，始终选择最高置信度的延续。最适合代码生成、数据提取和结构化输出。
- **默认温度 (1.0)：** 保留训练中的原始概率分布。
- **高温（1.5+）：** 使分布平坦，引入更多随机性。对于创造性任务很有用，但会增加输出不一致的风险。

单个token位置的概率分布变化示例：

|token候选者 |温度 1.5 时的概率 |温度下的概率 ~0.0 |原始 Logit |
|:---|:---:|:---:|:---:|
|懒惰| 0.4875 | 0.4875 0.9933 | 0.9933 2.0 |
|快| 0.2503 | 0.2503 0.0067 | 0.0067 1.0 |
|累了| 0.1285 | 0.1285 0.0000 | 0.0000 0.0 | 0.0
|慢| 0.0660 | 0.0000 | 0.0000 -1.0 |
|笨拙| 0.0339 | 0.0339 0.0000 | 0.0000 -2.0 |

### Top-p（细胞核采样）

Top-p 通过仅考虑累积概率超过阈值 p 的最小标记集来截断概率分布。 0.0 到 0.6 的 Top-p 与低温相结合，迫使模型进入狭窄的、确定性的执行路径，从而减少导致创造性拒绝和不必要总结的熵。

## 双子座思维层次配置

Google Gemini 3 模型用 `thinking_level` 参数替换了旧版 `thinking_budget`（内部推理的硬token计数上限），该参数提供了计算深度的相对指导。

|设置|闪存支持 |专业支持 |使用案例|
|:---|:---:|:---:|:---|
| `minimal` |是的 |没有 |高吞吐量、低延迟任务 |
| `low` |是的 |是的 |简单的指令遵循，数据提取 |
| `medium` |是的 |是（3.1 专业版）|中等复杂度任务 |
| `high` |是（默认）|是（默认）|复杂分析、代码生成、数学 |

重要限制：
- `thinking_level` 和 `thinking_budget` 是互斥的。在一个 API 调用中同时使用这两种方法会触发 HTTP 400 错误。
- 即使在 `low`，Gemini Pro 型号也会执行强制性的最低限度内部审议，以确保安全和对齐。
- 对于代码生成和复杂分析，设置为 `medium` 或 `high` 以获得与基线相比始终超过 92-95% 的质量分数。
- 避免将极低的温度与 `high` 思维水平结合起来，因为这有时会引发内部推理循环。
