# 架构模式

## 延迟加载技能

管理跨 AI 代理的大型上下文需求的标准模式是通过技能文件进行延迟加载提示工程。

技能是一个包含 `SKILL.md` 文件的文件夹，其中包含：

- **YAML 前面的内容：** 包含 `name` 和精确的 `description`。此元数据充当发现挂钩 - 代理在初始化期间仅读取此元数据（每个技能约 100 个token）。
- **Markdown 正文：** 完整的工作流程、规则和说明。仅当客服人员确定技能相关时才按需加载。

据记录，该架构使平均上下文使用量减少了 35%，并防止上下文稀释。但是，发现可靠性取决于 YAML 描述的特殊性：

|描述 质量 |发现成功率|
|:---|:---:|
| Vague（“帮助设计 API”）| 〜68% |
|具体（“使用 OpenAPI 规范设计 RESTful HTTP API，重点关注版本控制、错误代码和向后兼容性”）| 〜90% |

## 模型上下文协议（MCP）

MCP 是一个开放标准（由 Anthropic 首创，被 Google 和 OpenAI 采用），可实现LLM与外部数据源之间的实时、双向连接。

### 架构组件

- **主机：**包含LLM引擎的AI应用程序（IDE、终端工具、聊天机器人）。
- **客户端：** 主机内处理协议通信的内部桥。
- **服务器：** 向客户端公开数据库、API 或文档的外部服务。
- **传输：** 通过 stdio（本地）或 HTTP（远程）传输 JSON-RPC 2.0 消息。

### 它如何减少截断

如果没有 MCP，模型将依赖静态训练权重来实现事实主张。当这些权重过时时（例如，训练截止后发布了新的 API 版本），模型要么会产生一个看似合理的答案，要么会截断其响应以避免承诺具体细节。

使用 MCP，模型将当前文档直接提取到其上下文窗口中。这将模型从静态知识存储转变为基于实时数据运行的推理引擎，消除了产生幻觉或截断的动机。

### 示例：开发者知识 API

Google 的开发者知识 MCP 服务器对 Firebase、Android 和 Google Cloud 上的实时文档进行索引。当模型收到开发问题时：

1.它对实时索引执行 `search_document` 查询
2. 它评估返回的页面 URI
3.通过`get_document`或`batch_get_documents`获取完整文档内容
4.它根据当前的权威文档生成响应

这完全绕过了从过时的训练数据中编造答案的倾向。

## 分块任务执行

对于产生超出模型生成限制的输出的复杂任务，请将工作分解为连续的步骤：

1.先请求架构和结构（仅概要）
2. 单独请求每个组件并提供明确的完整性说明
3、所有组件生成后请求组装集成

这可以防止模型尝试估计总输出长度并抢先压缩其响应。
