# JSON Canvas 技巧

## 文件结构

画布文件 (`.canvas`) 包含两个遵循 [JSON Canvas Spec 1.0](https://jsoncanvas.org/spec/1.0/) 的顶级数组：

```json
{
  "nodes": [],
  "edges": []
}
```

- `nodes`（可选）：节点对象数组
- `edges`（可选）：连接节点的边缘对象数组

## 常见工作流程

### 1. 创建一个新画布

1.创建一个`.canvas`文件，其基本结构为`{"nodes": [], "edges": []}`
2. 为每个节点生成唯一的 16 个字符的十六进制 ID（例如 `"6f0ad84f44ce9c17"`）
3. 添加必填字段的节点：`id`、`type`、`x`、`y`、`width`、`height`
4. 通过 `fromNode` 和 `toNode` 添加引用有效节点 ID 的边
5. **验证**：解析 JSON 以确认其有效。验证节点数组中是否存在所有 `fromNode`/`toNode` 值

### 2. 将节点添加到现有画布

1.读取并解析现有的`.canvas`文件
2. 生成一个不与现有节点或边 ID 冲突的唯一 ID
3. 选择避免与现有节点重叠的位置（`x`、`y`）（留出50-100px间距）
4. 将新节点对象追加到 `nodes` 数组中
5. 可以选择添加将新节点连接到现有节点的边
6. **验证**：确认所有 ID 都是唯一的，并且所有边引用都解析为现有节点

### 3. 连接两个节点

1. 识别源节点和目标节点ID
2. 生成唯一的边缘ID
3. 将 `fromNode` 和 `toNode` 设置为源 ID 和目标 ID
4. 可选择设置`fromSide`/`toSide`（上、右、下、左）作为锚点
5. 可以选择为边缘的描述性文本设置 `label`
6. 将边附加到 `edges` 数组
7. **验证**：确认 `fromNode` 和 `toNode` 引用现有节点 ID

### 4. 编辑现有画布

1.读取并解析`.canvas`文件为JSON
2、通过`id`定位目标节点或边
3.修改需要的属性（文字、位置、颜色等）
4. 将更新后的 JSON 写回到文件中
5. **验证**：编辑后重新检查所有ID唯一性和边缘参考完整性

## 节点

节点是放置在画布上的对象。数组顺序决定 z-index：第一个节点 = 底层，最后一个节点 = 顶层。

### 通用节点属性

|属性 |必填|类型 |描述 |
|-----------|----------|------|-------------|
| `id` |是的 |字符串|唯一的 16 个字符的十六进制标识符 |
| `type` |是的 |字符串| `text`、`file`、`link` 或 `group` |
| `x` |是的 |整数 | X 位置（以像素为单位）|
| `y` |是的 |整数 | Y 位置（以像素为单位）|
| `width` |是的 |整数 |宽度（以像素为单位）|
| `height` |是的 |整数 |高度（以像素为单位）|
| `color` |没有 |画布颜色 |预设 `"1"`-`"6"` 或十六进制（例如，`"#FF0000"`）|

### 文本节点

|属性 |必填|类型 |描述 |
|-----------|----------|------|-------------|
| `text` |是的 |字符串|使用 Markdown 语法的纯文本 |

```json
{
  "id": "6f0ad84f44ce9c17",
  "type": "text",
  "x": 0,
  "y": 0,
  "width": 400,
  "height": 200,
  "text": "# Hello World\n\nThis is **Markdown** content."
}
```

**换行陷阱**：在 JSON 字符串中使用 `\n` 进行换行。不要**使用文字 `\\n` —— Obsidian 将其渲染为字符 `\` 和 `n`。

### 文件节点

|属性 |必填|类型 |描述 |
|-----------|----------|------|-------------|
| `file` |是的 |字符串|系统内文件的路径 |
| `subpath` |没有 |字符串|链接到标题或块（以 `#` 开头）|

```json
{
  "id": "a1b2c3d4e5f67890",
  "type": "file",
  "x": 500,
  "y": 0,
  "width": 400,
  "height": 300,
  "file": "Attachments/diagram.png"
}
```

### 链接节点

|属性 |必填|类型 |描述 |
|-----------|----------|------|-------------|
| `url` |是的 |字符串|外部网址 |

```json
{
  "id": "c3d4e5f678901234",
  "type": "link",
  "x": 1000,
  "y": 0,
  "width": 400,
  "height": 200,
  "url": "https://obsidian.md"
}
```

### 组节点

组是用于组织其他节点的可视容器。将子节点放置在组边界内。

|属性 |必填|类型 |描述 |
|-----------|----------|------|-------------|
| `label` |没有 |字符串|组的文本标签 |
| `background` |没有 |字符串|背景图像的路径|
| `backgroundStyle` |没有 |字符串| `cover`、`ratio` 或 `repeat` |

```json
{
  "id": "d4e5f6789012345a",
  "type": "group",
  "x": -50,
  "y": -50,
  "width": 1000,
  "height": 600,
  "label": "Project Overview",
  "color": "4"
}
```

## 边缘

边通过 `fromNode` 和 `toNode` ID 连接节点。

|属性 |必填|类型 |默认 |描述 |
|-----------|----------|------|---------|-------------|
| `id` |是的 |字符串| - |唯一标识符|
| `fromNode` |是的 |字符串| - |源节点ID |
| `fromSide` |没有 |字符串| - | `top`、`right`、`bottom` 或 `left` |
| `fromEnd` |没有 |字符串| `none` | `none` 或 `arrow` |
| `toNode` |是的 |字符串| - |目标节点ID |
| `toSide` |没有 |字符串| - | `top`、`right`、`bottom` 或 `left` |
| `toEnd` |没有 |字符串| `arrow` | `none` 或 `arrow` |
| `color` |没有 |画布颜色 | - |线条颜色 |
| `label` |没有 |字符串| - |文字标签|

```json
{
  "id": "0123456789abcdef",
  "fromNode": "6f0ad84f44ce9c17",
  "fromSide": "right",
  "toNode": "a1b2c3d4e5f67890",
  "toSide": "left",
  "toEnd": "arrow",
  "label": "leads to"
}
```

## 颜色

`canvasColor` 类型接受十六进制字符串或预设数字：

|预设|颜色 |
|--------|-------|
| `"1"` |红色|
| `"2"` |橙色|
| `"3"` |黄色|
| `"4"` |绿色|
| `"5"` |青色 |
| `"6"` |紫色|

预设颜色值故意未定义——应用程序使用自己的品牌颜色。

## ID 生成

生成16个字符的小写十六进制字符串（64位随机值）：

```
"6f0ad84f44ce9c17"
"a3b2c1d0e9f8a7b6"
```

## 布局指南

- 坐标可以为负（画布无限延伸）
- `x` 向右增加，`y` 向下增加；位置是左上角
- 空间节点间隔50-100px；在组内保留 20-50px 的内边距
- 与网格对齐（10 或 20 的倍数）以获得更清晰的布局

|节点类型 |建议宽度 |建议身高 |
|-----------|-----------------|------------------|
|小文字 | 200-300 | 80-150|
|中等文字 | 300-450 | 150-300 |
|大文字| 400-600 | 300-500 |
|文件预览 | 300-500 | 200-400 |
|链接预览 | 250-400 | 250-400 100-200 |

## 验证清单

创建或编辑画布文件后，验证：

1. 所有 `id` 值在节点和边上都是唯一的
2. 每个`fromNode`和`toNode`引用一个现有的节点ID
3. 每个节点类型都存在必填字段（文本节点为 `text`，文件节点为 `file`，链接节点为 `url`）
4. `type` 是以下之一：`text`、`file`、`link`、`group`
5. `fromSide`/`toSide` 值为以下之一：`top`、`right`、`bottom`、`left`
6. `fromEnd`/`toEnd` 值为以下之一：`none`、`arrow`
7. 颜色预设为 `"1"` 到 `"6"` 或有效的十六进制（例如，`"#FF0000"`）
8. JSON 有效且可解析

如果验证失败，请检查重复的 ID、悬空边缘引用或格式错误的 JSON 字符串（尤其是文本内容中未转义的换行符）。
