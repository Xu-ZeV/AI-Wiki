在编写任何代码之前，为某个功能塑造 UX 和 UI。此命令生成一个**设计概要**：一个结构化的工件，通过发现而不是猜测来指导实施。

**范围**：仅设计规划。该命令不编写代码。它产生使代码变得优秀的思维。

**输出**：设计概要，可以交给 $impeccable craft，或直接交给 $impeccable 进行自由形式的实施。当使用视觉方向探头时，图像是支持伪影，而不是主要输出。

## 理念

大多数人工智能生成的UI失败并不是因为代码不好，而是因为忽略了思考。他们跳到“这是一个卡片网格”，而不询问“用户想要完成什么？”这个命令反过来说：先理解深刻，执行起来才精确。

## 第一阶段：发现访谈

**在此阶段不要编写任何代码或做出任何设计决策。**您唯一的工作是足够深入地了解该功能，以便稍后做出出色的设计决策。

这是必需的交互，而不是可选的指导。在对话中提出这些问题，并根据答案进行调整。不要一次全部扔掉；进行自然对话。停止并使用 Codex 的结构化用户输入/问题工具（如果可用）；如果无法推断，请直接在聊天中询问以澄清您无法推断的内容。

### 采访节奏

发现至少包括一轮用户回答，除非 PRODUCT.md、DESIGN.md 或已确认的摘要直接回答所需的输入。对于稀疏提示，请勿合成完整的摘要以确认第一个响应。

- 使用安全带的结构化问题工具（如果存在）。否则，直接在聊天中询问并停止。
- 每轮提出 **2-3 个问题**，然后等待答案。
- 将 PRODUCT.md 和 DESIGN.md 视为锚点；它们减少了重复的问题，但**不**取代工艺的形状。形状是特定于任务的。
- 默认一轮。仅当第一个答案留下实质性空白时才添加第二个答案。不要仅仅为了感觉彻底而跑第二轮。
- 第一轮应阐明目的、受众/背景、内容/范围和（对于品牌）视觉方向。
- 第 2 轮在需要时填补仍然真正缺失的内容。

**先断言然后确认，而不是带有转义的菜单。** 当 PRODUCT.md 和用户提示使一个选项显而易见时，为其命名并要求用户确认或覆盖。不要列举“克制/承诺/或者其他什么？”作为一个真正的选择； “这读作克制，确认吗？”当答案已经明确时，胜过四选项菜单。

### 目的和背景
- 这个功能有什么用？它解决什么问题？
- 谁具体会使用它？ （不是“用户”；要具体：角色、背景、频率）
- 成功是什么样的？您如何知道此功能正在运行？
- 当用户使用此功能时，他们的心态是什么？ （着急？探索？焦虑？专注？）

### 内容和数据
- 此功能显示或收集哪些内容或数据？
- 现实的范围是多少？ （最小值、典型值、最大值，例如 0 项、5 项、500 项）
- 边缘情况是什么？ （空状态、错误状态、首次使用、高级用户）
- 内容是动态的吗？发生了什么变化以及多久发生一次？
- 哪些视觉资产是这里的真实内容？注意所需的图像、产品照片、插图、地图、纹理、图表、生成的对象或现有项目资产。

### 设计方向

在三个方面强制做出视觉决策。跳过任何 PRODUCT.md 或 DESIGN.md 已经回答的内容；只问缺少的东西。

- **此表面的颜色策略。** 选择一个：克制/承诺/全调色板/浸透。如果表面赢得了它，则可以覆盖项目默认值（例如，在其他受约束的产品内的湿透的英雄）。
- **通过场景句子主题。** 为该表面写一个物理上下文句子：谁使用它，在哪里，在什么环境光线下，在什么心情下。这句话迫使黑暗与光明。如果没有，请添加详细信息，直到出现为止。
- **两到三个命名锚参考。** 具体产品、品牌、物品。不是“现代”或“干净”之类的形容词。

### 范围

总是问。草图质量和发货质量是不同的输出；不要在他们之间猜测。

- **保真度。** 草图/中保真/高保真/生产就绪？
- **广度。** 一个屏幕/一个流程/整个表面？
- **交互性。** 静态视觉/交互式原型/出厂质量组件？
- **时间意图。** 快速探索，还是打磨直至发布？

范围答案是任务范围的。不要将它们写入 PRODUCT.md 或 DESIGN.md；仅在设计概要中携带它们。

### 约束
- 有技术限制吗？ （框架、性能预算、浏览器支持）
- 有内容限制吗？ （本地化、动态文本长度、用户生成的内容）
- 移动/响应式要求？
- WCAG AA 之外的辅助功能要求？

### 反目标
- 这不应该是什么？什么是错误的方向？
- 犯这个错误的最大风险是什么？

## 阶段 1.5：视觉方向探测（能力门控）

在发现访谈之后，当所有这些都成立时，**在**撰写最终摘要之前生成一小组视觉方向探针：

- 该作品是**全新**或方向模糊，视觉探索将澄清概要。
- 要求的保真度是**中保真度、高保真度或生产就绪**。跳过仅草图规划。
- 当前的工具为您提供本机图像生成（Codex 的 `image_gen`、等效的 MCP 工具或类似工具）。不要要求用户安装 API 或工具。

当满足这些条件时，此步骤是强制性的。如果图像生成本身不可用，请勿要求用户安装 API 或工具。在一行中说明由于该工具缺少本机图像生成而跳过图像步骤，然后继续。一行公告是必须的，不是可选的；它迫使人们做出有意识的决定，而不是让这一步悄然消失。

使用探针探索视觉通道，而不是取代简报。

不要跳过探测，因为最终的 UI 将是语义的、可编辑的、代码本机的、响应式的或可访问的。这些是实现要求，而不是避免视觉探索的理由。

### 生成什么

根据发现答案生成 **2 到 4** 不同方向的探测，特别是：

- 色彩策略
- 主题场景句
- 命名锚参考
- 范围和保真度

探针应该在主要视觉方向（层次结构、拓扑、密度、印刷声音或颜色策略）上有所不同，而不仅仅是调色板调整。

### 如何使用探针

- 将它们视为**方向测试**，而不是最终设计。
- 使用它们来压力测试简报是否指向正确的车道。
- 询问用户哪个方向感觉最接近，什么感觉不好，以及什么应该继续发展。
- 如果调查显示不匹配，请在最终确定摘要之前修改摘要输入。

### 重要限制

- **不要**跳过发现，因为可以生成图像。
- **不要**将生成的图像视为最终的用户体验规范、最终副本或最终的可访问性行为。
- **不要**使用此步骤对现有工作进行细微改进。它是为了塑造一个新的表面或澄清一个大的方向选择。

如果图像生成本身不可用，请在一行中宣布跳过并继续设计简介。

## 第 2 阶段：设计概要

在采访和任何必要的调查之后，提出一个简短的内容并**结束你的回应**。用户必须在任何实施运行之前进行确认。不要呈现摘要，然后继续以相同的响应进行编码，即使摘要对您来说很明显。用户的确认就是闸门。

**根据答案的清晰程度选择简短的形状：**

- **紧凑的形式（3-5 个项目符号）** 当发现很清晰并且原始提示 + PRODUCT.md 已经固定范围、内容和方向时。说明您正在构建的内容、视觉通道，并以一两个具体问题或明确的“确认还是覆盖？”结束。迅速的。这是具有明确提示的典型工艺请求的默认设置。
- **完整的结构化形式（下面的部分）** 当任务确实不明确、多屏幕时，或者当用户要求将形状作为独立步骤时。当结构规则发挥作用时，请使用此方法。

不要将清晰的内裤塞进长的内裤中以显得彻底。 70 行简短的重述用户刚刚给出的答案只是噪音，而不是严谨的。同样，不要为了看起来高效而跳过确认暂停：暂停就是重点。

呈现简报，然后**停下来等待明确的确认**。您无法判断用户是否已经批准。即使感觉简报明显正确，也要询问一次并等待。停顿是将形状与过早实施区分开来的。

### 简要结构

**1.功能摘要**（2-3 句话）
这是什么，它是为谁服务的，它需要完成什么。

**2.主要用户操作**
用户在这里应该做或理解的最重要的事情。

**3.设计方向**
色彩策略（克制/承诺/全调色板/浸透）+主题场景句子+2-3个命名锚参考。参考 PRODUCT.md 和 DESIGN.md 已经回答的地方，并记下任何每个表面的覆盖。

如果您运行了“视觉方向探测”步骤，请指出哪个探测方向获胜，以及简报中因此发生的变化。

**4.范围**
采访范围部分的保真度、广度、互动性和时间意图。任务范围；这些不会在简报之外持续存在。

**5.布局策略**
高级空间方法：什么是重点，什么是次要的，信息如何流动。描述视觉层次和节奏，而不是具体的 CSS。

**6。关键国家**
列出该功能所需的每个状态：默认、空、加载、错误、成功、边缘情况。对于每一个，记下用户需要看到和感受到的内容。

**7.交互模型**
用户如何与此功能交互。单击、悬停、滚动时会发生什么？他们得到什么反馈？从进入到完成的流程是怎样的？

**8.内容要求**
需要什么副本、标签、空状态消息、错误消息和微副本。注意任何动态内容及其实际范围。对于图像主导的表面，还列出所需的图像/媒体角色及其可能的来源（项目资源、生成的栅格、语义 SVG/CSS、画布/WebGL、图标库或接受的省略）。

**9.推荐参考**
根据简介，列出哪些无可挑剔的参考文件在实施过程中最有价值（例如，用于复杂布局的layout.md、用于动画功能的animate.md、用于表单重功能的interaction-design.md、用于版式驱动页面的typeset.md、用于颜色主导品牌的colorize.md）。

**10.开放式问题**
任何真正未解决的事情。不要列出您已经建议默认的“开放问题”；断言默认值并继续。如果您在问题旁边写下 `Recommend: X`，则只需选择 X。

如果用户不同意任何部分，请重新审视相关的发现问题。在用户确认方向之前，形状运行是不完整的。
