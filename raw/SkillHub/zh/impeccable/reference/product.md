# 产品注册

当设计服务于产品时：应用程序 UI、管理仪表板、设置面板、数据表、工具、经过身份验证的界面以及用户执行任务的任何内容。

## 产品斜率测试

不是“有人会说这是人工智能创造的”。熟悉通常是这里的一个特点。测试是：熟悉该类别最好工具（Linear、Figma、Notion、Raycast、Stripe）的用户会坐下来信任这个界面，还是会在每个微妙的组件处停下来？

产品 UI 的失败模式不是扁平化，而是毫无目的的奇怪：过度装饰的按钮、不匹配的表单控件、无意义的动作、在标签应有的位置显示字体、为标准任务发明可供性。酒吧是赢得熟悉的。该工具应该消失在任务中。

## 版式

- **一个系列通常是正确的。** 产品 UI 不需要显示屏/机身配对。精心调整的 sans 包含标题、按钮、标签、正文、数据。
- **固定 rem 比例，而不是流动的。** 夹形标题不服务于产品 UI。用户以一致的 DPI 观看，侧边栏中缩小的流畅 h1 看起来更糟，而不是更好。
- **更严格的比例。** 步骤之间的比例为 1.125–1.2 是典型的。这里的字体元素比品牌表面更多；夸张的对比度会产生噪音。
- **行长仍然适用于散文**（65–75ch）。数据和紧凑的UI可以更密集地运行； 120ch+ 的桌子就很好了。

## 颜色

产品默认为受限。单一表面可以赢得承诺（仪表板，其中一种类别颜色带有报告，带有湿透的欢迎屏幕的入职流程），但限制是地板。

- 状态丰富的语义词汇：悬停、焦点、活动、禁用、选定、加载、错误、警告、成功、信息。将这些标准化。
- 强调色仅用于主要操作、当前选择和状态指示器，而不是装饰。
- 用于侧边栏、工具栏和面板的第二个中性层（比内容表面稍冷或稍暖）。

## 布局

- 响应行为是结构性的（折叠侧边栏、响应式表格、断点驱动列），而不是流畅的排版。

## 组件

每个交互组件都有：默认、悬停、焦点、活动、禁用、加载、错误。不要运送其中的一半。

- 用于加载的骨架状态，而不是内容中间的旋转器。
- 教导界面的空状态，而不是“这里什么都没有”。
- 表面上一致的可供性。相同的按钮形状。相同的形式控制词汇。相同的图标风格。

## 运动

- 大多数转换为 150–250 毫秒。用户处于流量之中；不要让他们等待编舞。
- 动作传达状态，而不是装饰。状态改变、反馈、加载、揭示：仅此而已。
- 没有精心安排的页面加载序列。产品加载到任务中；用户不想看到它加载。

## 产品禁令（除了共享的绝对禁令之外）

- 不传达状态的装饰性动作。
- 跨屏幕的组件词汇不一致。如果“保存”按钮在两个地方看起来不同，则其中一个地方是错误的。
- 在 UI 标签、按钮、数据中显示字体。
- 重新发明风味的标准可供性（自定义滚动条、奇怪的表单控件、非标准模式）。
- 非活动状态下的重色或全饱和度强调。
- 模态作为第一个想法。情态动词通常是懒惰的。首先排除内联/渐进式替代方案。

## 产品权限

产品可以提供品牌表面无法提供的东西。

- 系统字体和熟悉的无默认值（Inter、SF Pro、系统 UI 堆栈）。
- 标准导航模式：顶栏+侧导航、面包屑、选项卡、命令面板。
- 密度。具有许多行的表格、具有许多标签的面板、用户需要时的密集信息。
- 一致性胜过惊喜。屏幕与屏幕之间的视觉词汇相同是一种美德；快乐只停留在瞬间，而不是一页纸。
