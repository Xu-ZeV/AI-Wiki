空间是最未被充分利用的设计工具。找到布局的实际问题（单调间距、弱层次结构、相同的卡片网格）并修复结构，而不是表面。

---

## 注册

品牌：不对称构图，`clamp()` 的流体间距，故意打破网格以强调。对比中的节奏：紧密的组合与宽松的分离相结合。

产品：可预测的网格、一致的密度、熟悉的导航模式。响应行为是结构性的（折叠侧边栏、响应式表格），而不是流畅的排版。一致性是一种可供性。

---

## 评估当前布局

分析当前空间设计的薄弱环节：

1. **间距**：
   - 间距是一致的还是任意的？ （随机填充/边距值）
   - 所有间距都一样吗？ （各处填充均等 = 无节奏）
   - 相关元素是否紧密分组，组之间有足够的空间？

2. **视觉层次**：
   - 应用斜视测试：模糊你的（隐喻的）眼睛。您还能确定最重要的元素、第二重要的元素以及清晰的分组吗？
   - 等级制度是否有效实现？ （仅空间和重量就足够了；当前的方法有效吗？）
   - 空白是否能引导人们注意重要的事情？

3. **网格和结构**：
   - 是否有清晰的底层结构，或者布局是否感觉随意？
   - 到处都使用相同的卡片网格吗？ （图标+标题+文字，不断重复）

4. **节奏和多样性**：
   - 布局有视觉节奏吗？ （紧密/宽松间距交替）
   - 每个部分的结构是否相同？ （单调重复）
   - 是否有故意的惊喜或强调时刻？

5. **密度**：
   - 布局是否太局促？ （没有足够的喘息空间）
   - 布局是否太稀疏？ （无目的的过多空白）
   - 密度与内容类型匹配吗？ （数据密集的UI需要更紧密的间距；营销页面需要更多的空间）

**关键**：即使颜色和字体都很好，布局问题通常也是界面感觉“不合适”的根本原因。空间是一种设计素材；有意识地使用它。

## 计划布局改进

制定系统的计划：

- **间距系统**：使用一致的比例（框架的内置比例，如 Tailwind、基于 rem 的token或自定义系统）。具体值比一致性更重要。
- **层次结构策略**：空间将如何传达重要性？
- **布局方法**：什么结构适合内容？用于 1D 的 Flex、用于 2D 的 Grid、用于复杂页面布局的命名区域。
- **节奏**：哪些地方的间距应该紧，什么地方应该宽？

## 系统地改进布局

### 建立间距系统

- 使用一致的间距比例（Tailwind 等框架比例、基于 rem 的标记或自定义比例都可以）。重要的是值来自定义的集合，而不是任意数字。
- 与 8pt 相比，更喜欢 4pt 基本比例（4、8、12、16、24、32、48、64、96px）； 8pt 太粗，您经常需要 8 到 16 之间的 12px。
- 如果使用自定义属性，则按语义命名标记：`--space-xs` 到 `--space-xl`，而不是 `--spacing-8`
- 使用 `gap` 作为同级间距而不是边距；消除保证金崩溃黑客攻击
- 应用 `clamp()` 实现在更大屏幕上呼吸的流体间距

### 创造视觉节奏

- **相关元素紧密分组**（兄弟元素之间为 8-12px）
- **不同部分之间有较大的分隔**（48-96px）
- **各部分内的间距**不同（并非每行都需要相同的间隙）
- **不对称构图**：当内容邀请时的深思熟虑的选择（不是默认的追逐）。

### 选择正确的布局工具

- **使用 Flexbox 进行一维布局**：项目行、导航栏、按钮组、卡片内容、大多数组件内部结构。
- **使用网格进行 2D 布局**：页面级结构、仪表板、数据密集界面、行和列需要协调控制的任何内容。
- 使用命名网格区域（`grid-template-areas`）进行复杂的页面布局；在断点处重新定义。
- 对组件使用**容器查询**，对页面布局使用视口查询。狭窄侧边栏中的卡片可以保持紧凑，而主要内容区域中的同一张卡片会自动扩展：

```css
.card-container { container-type: inline-size; }
.card { display: grid; gap: var(--space-md); }
@container (min-width: 400px) {
  .card { grid-template-columns: 120px 1fr; }
}
```

### 打破卡牌网格的单调

- 不要默认所有事情都使用卡片网格；间距和对齐方式自然地创建视觉分组
- 仅当内容真正独特且可操作时才使用卡片。切勿将卡片嵌套在卡片内
- 改变卡片大小、跨越列或将卡片与非卡片内容混合以打破重复

### 加强视觉层次

- 使用清晰层次结构所需的最少维度。光有空间就足够了；元素周围大量的空白吸引眼球。一些最精美的设计仅通过空间和重量就达到了节奏。仅当简单的方法不够时才添加颜色或尺寸对比。
- 最好的层次结构同时结合了 2-3 个维度。一个更大、更粗、并且上面有更多空间的标题读起来就是主要的，而不需要尝试：

|工具|强层次结构 |弱层次结构|
|------|------------------|----------------|
| **尺寸** | 3:1 比例或以上 | <2:1 比例 |
| **重量** |粗体与常规|中等与常规|
| **颜色** |高对比度|类似的音调|
| **职位** |上/左（主要）|下/右 |
| **空间** |被白色空间包围 |拥挤|

- 注意阅读流程：在 LTR 语言中，眼睛自然地从左上角扫描到右下角，但主要操作位置取决于上下文（例如，对话框中的右下角、导航中的顶部）。
- 通过邻近和分离创建清晰的内容分组。

### 管理深度和高度

- 建立一致的阴影比例（sm → md → lg → xl）；阴影应该是微妙的
- 使用立面来强化层次结构，而不是作为装饰

### 光学调整

- 如果一个图标尽管在几何上居中，但在视觉上看起来偏离中心，请轻推它。但前提是你确信它看起来确实是错误的。不要投机性地调整。
- 由于字母空白，`margin-left: 0` 处的文本看起来略有缩进；负边距 (`-0.05em`) 可对其进行光学对齐。几何居中的字形通常看起来偏离中心（播放图标需要向右移动，箭头向其方向移动）。
- 即使视觉元素较小，触摸目标也必须最小为 44×44 像素。使用 padding 或伪元素扩展点击区域：

```css
.icon-button { width: 24px; height: 24px; position: relative; }
.icon-button::before {
  content: ''; position: absolute; inset: -10px;
}
```

**从不**：
- 使用比例之外的任意间距值
- 使所有间距相等（多样性创造层次结构）
- 将所有东西都包裹在卡片中（并非所有东西都需要容器）
- 在卡片内嵌套卡片（使用间距和分隔符来实现内部层次结构）
- 到处使用相同的卡片网格（图标+标题+文本，重复）
- 默认以英雄度量布局（大数字、小标签、统计数据、渐变）作为模板。如果显示真实的用户数据，突出的指标可以发挥作用，但它应该显示实际数据，而不是装饰性数字。

## 验证布局改进

- **斜视测试**：您能识别主要、次要和视力模糊的分组吗？
- **节奏**：页面是否有令人满意的紧凑和宽敞的间距节拍？
- **层次结构**：最重要的内容是否在 2 秒内显而易见？
- **呼吸空间**：布局是否感觉舒适，不拥挤或浪费？
- **一致性**：间距系统是否统一应用？
- **响应能力**：布局是否能够在不同屏幕尺寸之间优雅地适应？

当节奏和层次落地时，将最后的传递交给`$impeccable polish`。

## 实时模式签名参数

每个变体必须声明一个 `density` 参数。通过 `calc(var(--p-density, 1) * <base>)` 驱动变体范围 CSS 中的所有间距标记：填充、间隙、列宽。用户从通风滑到拥挤，并看到布局重新呼吸而没有再生。

```json
{"id":"density","kind":"range","min":0.6,"max":1.4,"step":0.05,"default":1,"label":"Density"}
```

对于拓扑真正发生变化的变体（堆叠与并排、网格与便当），请使用 `steps` 参数，其范围 CSS 分支通过 `:scope[data-p-structure="X"]`。一个结构参数+一个密度参数是一个强大的组合；拒绝添加第三个。

```json
{"id":"structure","kind":"steps","default":"grid","label":"Structure","options":[
  {"value":"stacked","label":"Stacked"},
  {"value":"grid","label":"Grid"},
  {"value":"bento","label":"Bento"}
]}
```

有关完整的参数合约，请参阅 `reference/live.md`。
