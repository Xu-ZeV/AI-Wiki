开始你的回应：

```

》》》 Entering overdrive mode...
```

将界面推向传统极限。这不仅仅是视觉效果。它是关于利用浏览器的全部功能使界面的任何部分都感觉非凡：一个处理一百万行的表格，一个根据触发器变形的对话框，一个通过流反馈实时验证的表单，一个感觉电影般的页面转换。

**此命令非常重要**：上下文决定了“非凡”的含义。创意组合中的粒子系统令人印象深刻。设置页面上相同的粒子系统令人尴尬。但是具有即时乐观保存和动画状态转换的设置页面呢？这也很了不起。在决定什么是合适的之前，先了解项​​目的个性和目标。

### 建造前提出建议

该命令最有可能失败。不要直接跳入实施。你必须：

1. **思考 2-3 个不同的方向**：考虑不同的技术、野心水平和审美方法。对于每个方向，简要描述结果的外观和感觉。
2. **停止并使用 Codex 的结构化用户输入/问题工具（如果可用）；如果不可用，请直接在聊天中询问以澄清您无法推断的内容。**在编写任何代码之前呈现这些指示并获得用户的选择。解释权衡（浏览器支持、性能成本、复杂性）。
3. 仅按照用户确认的方向进行。

跳过这一步可能会产生一些令人尴尬的东西，需要扔掉。

### 使用浏览器自动化进行迭代

技术上雄心勃勃的效果几乎从来不会在第一次尝试时就奏效。您必须积极使用浏览器自动化工具来预览您的工作，直观地验证结果并进行迭代。不要假设效果看起来不错，检查一下。期待多轮细化。 “技术上可行”和“看起来非凡”之间的差距是通过视觉迭代而不是仅通过代码来缩小的。

## 评估“非凡”在这里意味着什么

正确的技术抱负完全取决于您正在从事的工作。在选择技术之前，问：**什么会让这个特定界面的用户说“哇，这很好”？**

### 用于视觉/营销表面
页面、英雄部分、登陆页面、作品集：“哇”通常是感官上的：滚动驱动的显示、着色器背景、电影页面过渡、响应光标的生成艺术。

### 对于功能性 UI
表格、表单、对话框、导航：“哇”在于它的感觉：一个从通过视图转换触发它的按钮变形而来的对话框，一个通过虚拟滚动以 60fps 渲染 100k 行的数据表，一个带有流式验证的表单，感觉是即时的，通过弹簧物理进行拖放。

### 对于性能关键的 UI
“哇”是看不见的，但却能感觉到：一个可以无闪烁地过滤 50k 个项目的搜索，一个永远不会阻塞主线程的复杂形式，一个近乎实时处理的图像编辑器。界面从不犹豫。

### 对于数据量大的接口
图表和仪表板：“哇”在于流动性：通过 Canvas/WebGL 对海量数据集进行 GPU 加速渲染、数据状态之间的动画转换、自然稳定的力导向图形布局。

**共同点**：有关实现的某些内容超出了用户对 Web 界面的期望。技术是为体验服务的，而不是相反。

## 工具包

根据您想要实现的目标而不是技术名称来组织。

### 让过渡感觉像电影
- **View Transitions API**（同一文档：所有浏览器；跨文档：无 Firefox）：状态之间共享元素变形。扩展到详细信息页面的列表项。一个按钮变成了一个对话框。这是最接近原生 FLIP 动画的东西。
- **`@starting-style`**（所有浏览器）：将 `display: none` 中的元素动画化为仅使用 CSS 可见，包括条目关键帧
- **弹簧物理学**：具有质量、张力和阻尼的自然运动，而不是三次贝塞尔曲线。库：运动（以前称为 Framer Motion）、GSAP，或推出您自己的弹簧解算器。

### 将动画绑定到滚动位置
- **滚动驱动的动画** (`animation-timeline: scroll()`)：仅 CSS，无 JS。视差、进度条、显示序列均由滚动位置驱动。 （Chrome/Edge/Safari；Firefox：仅标记；始终提供静态后备）

### 超越 CSS 的渲染
- **WebGL**（所有浏览器）：着色器效果、后处理、粒子系统。库：Three.js、OGL（轻量级）、regl。用于CSS无法表达的效果。
- **WebGPU**（Chrome/Edge；Safari 部分；Firefox：仅标志）：下一代 GPU 计算。比 WebGL 更强大，但浏览器支持有限。始终回退到 WebGL2。
- **Canvas 2D / OffscreenCanvas**：自定义渲染、像素操作或通过 Web Workers + OffscreenCanvas 完全将繁重的渲染移出主线程。
- **SVG 过滤器链**：位移图、湍流、有机扭曲效果的形态。 CSS 可动画。

### 让数据充满活力
- **虚拟滚动**：仅呈现包含数万个项目的表/列表的可见行。简单案例不需要库； TanStack Virtual 适用于复杂的情况。
- **GPU 加速图表**：Canvas 或 WebGL 渲染的数据可视化，适用于对于 SVG/DOM 来说太大的数据集。库：deck.gl，基于 regl 的自定义渲染器。
- **动画数据转换**：图表状态之间变形而不是替换。 D3 的 `transition()` 或基于 DOM 图表的视图转换。

### 动画复杂属性
- **`@property`**（所有浏览器）：使用类型注册自定义 CSS 属性，启用 CSS 通常无法插入的渐变、颜色和复杂值的动画。
- **Web 动画 API**（所有浏览器）：具有 CSS 性能的 JavaScript 驱动动画。可组合、可取消、可逆。复杂编排的基础。

### 突破性能极限
- **Web Workers**：将计算移出主线程。繁重的数据处理、图像处理、搜索索引：任何会导致卡顿的事情。
- **OffscreenCanvas**：在工作线程中渲染。主线程保持空闲，而复杂的视觉效果在后台渲染。
- **WASM**：计算量大的功能接近本机性能。图像处理、物理模拟、编解码器。

### 与设备交互
- **网络音频 API**：空间音频、音频反应可视化、声音反馈。需要用户手势才能启动。
- **设备 API**：方向、环境光、地理位置。谨慎使用并始终在用户许可的情况下使用。

**注意**：此命令是为了增强界面的感觉，而不是改变产品的功能。添加实时协作、离线支持或新的后端功能是产品决策，而不是 UI 增强。专注于让现有功能感觉非凡。

## 严格执行

### 渐进增强是没有商量余地的

每种技术都必须优雅地降级。没有增强的体验一定还是不错的。

```css
@supports (animation-timeline: scroll()) {
  .hero { animation-timeline: scroll(); }
}
```

```javascript
if ('gpu' in navigator) { /* WebGPU */ }
else if (canvas.getContext('webgl2')) { /* WebGL2 fallback */ }
/* CSS-only fallback must still look good */
```

### 表演规则

- 目标 60 fps。如果低于 50，请简化。
- 始终尊重 `prefers-reduced-motion`。提供一个漂亮的静态替代方案。
- 仅在靠近视口时延迟初始化大量资源（WebGL 上下文、WASM 模块）。
- 暂停离屏渲染。杀死你看不到的东西。
- 在真正的中端设备上进行测试，而不仅仅是您的开发机器。

### 波兰语就是区别

“酷”和“非凡”之间的差距在于最后 20% 的细化：弹簧动画上的缓和曲线、交错显示中的时间偏移、使过渡感觉物理的微妙的辅助运动。不要发布第一个有效的版本；发布感觉不可避免的版本。

**从不**：
- 忽略 `prefers-reduced-motion`。这是可访问性要求，而不是建议
- 在中端设备上造成卡顿的船舶效果
- 使用前沿 API，无需功能回退
- 添加声音而无需用户明确选择加入
- 利用技术野心来掩盖薄弱的设计基础；首先使用其他命令修复这些问题
- 叠加多个相互竞争的非凡时刻。专注产生影响，过度产生噪音

## 验证结果

- **哇测试**：向没有看过它的人展示。他们有反应吗？
- **移除测试**：将其拿走。体验是否感觉减弱，或者没有人注意到？
- **设备测试**：在手机、平板电脑、Chromebook 上运行。还顺利吗？
- **可访问性测试**：启用减少运动。还美丽吗？
- **背景测试**：这对于这个品牌和受众有意义吗？

“技术非凡”并不是指使用最新的 API。它是让界面做一些用户认为网站不能做的事情。
