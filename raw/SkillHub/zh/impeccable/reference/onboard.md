> **需要额外的背景**：您希望用户达到的“顿悟时刻”以及用户的体验水平。

尽快让用户获得第一价值。入职培训的工作不是教授产品。它的工作是让人们知道该产品值得他们花时间。

## 评估入职需求

了解用户需要学习什么以及为什么：

1. **确定挑战**：
   - 用户想要实现什么目标？
   - 目前的经验有哪些令人困惑或不清楚的地方？
   - 用户在哪里陷入困境或流失？
   - 我们希望用户达到的“顿悟时刻”是什么？

2. **了解用户**：
   - 他们的经验水平如何？ （初学者、高级用户、混合型？）
   - 他们的动机是什么？ （兴奋探索？工作需要？）
   - 他们的时间投入是多少？ （5分钟？30分钟？）
   - 他们知道什么替代方案？ （来自竞争对手？新类别？）

3. **定义成功**：
   - 用户要成功至少需要学习什么？
   - 我们希望他们采取什么关键行动？ （第一个项目？第一次邀请？）
   - 我们如何知道入职是否有效？ （完成率？实现价值的时间？）

**关键**：入职培训应该让用户尽快实现价值，而不是教授一切可能的东西。

## 入职原则

遵循以下核心原则：

### 展示，而不是讲述
- 用工作示例进行演示，而不仅仅是描述
- 在入门中提供真正的功能，而不是单独的教程模式
- 使用渐进式披露，一次教一件事

### 使其可选（如果可能）
- 让有经验的用户跳过入门阶段
- 不要阻止对产品的访问
- 提供“跳过”或“我自己探索”选项

### 实现价值的时间
- 尽快让用户进入“顿悟时刻”
- 前置最重要的概念
- 教授 20%，带来 80% 的价值
- 保存高级功能以供上下文发现

### 仪式背景
- 在用户需要时教授功能，而不是预先教授
- 空状态是入职机会
- 使用时的工具提示和提示

### 尊重用户智慧
- 不要居高临下或过度解释
- 简洁明了
- 假设用户可以找出标准模式

## 设计入职体验

为上下文创建适当的入职培训：

### 初始产品入门

**欢迎屏幕**：
- 清晰的价值主张（这个产品是什么？）
- 用户将学习/完成什么
- 时间估算（诚实承诺）
- 跳过选项（对于有经验的用户）

**帐户设置**：
- 所需信息最少（稍后收集更多信息）
- 解释你为什么要求每条信息
- 尽可能智能默认
- 适当时社交登录

**核心概念介绍**：
- 介绍1-3个核心概念（不是全部）
- 使用简单的语言和例子
- 尽可能进行互动（做，而不仅仅是阅读）
- 进度指示（第 1 步，共 3 步）

**第一次成功**：
- 引导用户完成一些真实的事情
- 预先填充的示例或模板
- 庆祝完成（但不要过度）
- 明确后续步骤

### 功能发现和采用

**空状态**：
显示以下内容而不是空格：
- 这里会出现什么（描述+屏幕截图/插图）
- 为什么它有价值
- 清除 CTA 以创建第一个项目
- 示例或模板选项

示例：
```
No projects yet
Projects help you organize your work and collaborate with your team.
[Create your first project] or [Start from template]
```

**上下文工具提示**：
- 在相关时刻出现（用户第一次看到功能）
- 直接指向相关的 UI 元素
- 简要说明+好处
- 可忽略（带有“不再显示”选项）
- 可选的“了解更多”链接

**功能公告**：
- 在新功能发布时突出显示它们
- 展示新内容及其重要性
- 让用户立即尝试
- 可驳回

**渐进式入职**：
- 当用户遇到功能时教授它们
- 新/未使用功能的徽章或指示器
- 逐渐解锁复杂性（不要立即显示所有选项）

### 导游和演练

**何时使用**：
- 具有许多功能的复杂界面
- 对现有产品的重大改变
- 需要领域知识的行业特定工具

**如何设计**：
- 聚焦特定的 UI 元素（页面其余部分变暗）
- 保持简短的步数（每次游览最多 3-7 步）
- 允许用户自由点击游览
- 包括“跳过游览”选项
- 使可重播（帮助菜单）

**最佳实践**：
- 互动而非被动（让用户点击真正的按钮）
- 专注于工作流程，而不是功能（“创建项目”而不是“这是项目按钮”）
- 提供样本数据以便行动有效

### 互动教程

**何时使用**：
- 用户需要亲自实践
- 概念复杂或不熟悉
- 高风险（最好在安全的环境中练习）

**如何设计**：
- 带有示例数据的沙箱环境
- 明确的目标（“创建按地区显示销售额的图表”）
- 分步指导
- 验证（确认他们做得正确）
- 毕业时刻（你准备好了！）

### 文档和帮助

**产品内帮助**：
- 整个界面的上下文帮助链接
- 键盘快捷键参考
- 可搜索的帮助中心
- 复杂工作流程的视频教程

**帮助模式**：
- 复杂功能附近的 `?` 图标
- 工具提示中的“了解更多”链接
- 键盘快捷键提示（搜索框中显示 `⌘K`）

## 空状态设计

每个空状态都需要：

### 这里会发生什么
“您最近的项目将出现在这里”

### 为什么它很重要
“项目可以帮助您组织工作并与团队协作”

### 如何开始
[创建项目]或[从模板导入]

### 视觉兴趣
插图或图标（不仅仅是空白页上的文字）

### 上下文帮助
“需要入门帮助吗？[观看 2 分钟教程]”

**空状态类型**：
- **首次使用**：从未使用过此功能（强调价值，提供模板）
- **用户清除**：故意删除所有内容（轻触，易于重新创建）
- **无结果**：搜索或过滤器未返回任何内容（建议不同的查询，清除过滤器）
- **无权限**：无法访问（解释原因，如何获得访问权限）
- **错误状态**：加载失败（解释发生了什么，重试选项）

## 实现模式

### 技术方法：

**工具提示库**：Tippy.js、Popper.js
**游览库**：Intro.js、Shepherd.js、React Joyride
**模态模式**：焦点陷阱、背景、ESC 关闭
**进度跟踪**：“已看到”状态的本地存储
**分析**：跟踪完成情况、下车点

**存储模式**：
```javascript
// Track which onboarding steps user has seen
localStorage.setItem('onboarding-completed', 'true');
localStorage.setItem('feature-tooltip-seen-reports', 'true');
```

**重要**：不要两次显示相同的入门信息（烦人）。跟踪完成情况并尊重解雇。

**从不**：
- 强制用户经过长时间的入职培训才能使用产品
- 通过明显的解释来惠顾用户
- 重复显示相同的工具提示（尊重解雇）
- 游览期间阻止所有 UI（让用户探索）
- 创建与真实产品无关的单独教程模式
- 预先信息淹没（逐步披露！）
- 隐藏“跳过”或使其难以找到
- 忘记回访用户（不再显示初始登录）

## 验证入职质量

与真实用户进行测试：

- **完成时间**：用户能否快速完成入职？
- **理解力**：用户完成后是否理解？
- **行动**：用户是否采取所需的下一步？
- **跳过率**：是否有太多用户跳过？ （可能太长或者没有价值）
- **完成率**：用户是否完成？ （如果低，则简化）
- **价值实现时间**：用户获得第一个价值需要多长时间？

当用户快速顿悟并且不放弃时，将最后的传递交给 `$impeccable polish`。
