版式承载了页面上的大部分信息。将通用默认值（Inter、Roboto、平面比例的系统后备）替换为反映品牌和有意对比的比例的类型。

## 注册

Brand：运行[brand.md](brand.md)中的字体选择程序。流体 `clamp()` 刻度，步距比≥1.25。

产品：系统字体和熟悉的无堆栈在这里是合法的。一个经过精心调整的系列通常承载整个UI。修复了 `rem` 比例，更紧密间隔的步骤之间的比率为 1.125–1.2。

## 评估当前的版式

分析当前类型的弱点或通用之处：

1. **字体选择**：
   - 我们是否使用不可见的默认值？ （Inter、Roboto、Arial、Open Sans、系统默认值）
   - 字体是否符合品牌个性？ （好玩的品牌不应该使用企业字体）
   - 字体系列是否过多？ （超过2-3几乎总是一团糟）

2. **层次结构**：
   - 你能一眼看出标题、正文和说明吗？
   - 字体大小是否太接近？ （14px、15px、16px = 混乱的层次结构）
   - 重量对比是否足够强烈？ （中型与常规型几乎不可见）

3. **尺寸和比例**：
   - 是否有一致的字体比例，或者尺寸是任意的？
   - 正文是否满足最低可读性？ （16 像素以上）
   - 规模调整策略是否适合具体情况？ （修复了应用程序 UI 的 `rem` 比例；用于营销/内容页面标题的流畅 `clamp()`）

4. **可读性**：
   - 线条长度舒适吗？ （最好是 45-75 个字符）
   - 行高适合字体和上下文吗？
   - 文字和背景之间的对比度是否足够？

5. **一致性**：
   - 相同的元素是否始终以相同的方式设计？
   - 字体粗细的使用是否一致？ （同一角色的某一部分未加粗，另一部分为半加粗）
   - 字母间距是故意的还是默认的？

**关键**：目标不是让文本变得“更精美”。这是为了让它更清晰、更具可读性、更有目的性。好的排版是看不见的；糟糕的排版会分散注意力。

## 计划版式改进

请参阅下面的 [参考资料](#reference-material) 部分，了解有关缩放、配对和加载策略的详细指导。

制定系统的计划：

- **字体选择**：字体需要更换吗？什么适合品牌/环境？
- **类型尺度**：建立具有清晰层次结构的模块化尺度（例如1.25比率）
- **权重策略**：哪些权重服务于哪些角色？ （正文为常规，标签为半粗体，标题为粗体，或任何合适的内容）
- **间距**：行高、字母间距和印刷元素之间的边距

## 系统地改进版式

### 字体选择

如果字体需要更换：
- 选择反映品牌个性的字体
- 与真正的对比（衬线 + 无衬线、几何 + 人文主义）配对，或使用多个粗细的单一系列
- 确保网页字体加载不会导致布局偏移（`font-display: swap`，公制匹配的后备）

### 建立层次结构

建立清晰的字体规模：
- **5 种尺寸满足大多数需求**：标题、次要、正文、副标题、标题
- **在级别之间使用一致的比率**（1.25、1.333 或 1.5）
- **组合尺寸**：尺寸+重量+颜色+空间，形成强烈的层次结构。不要仅仅依赖尺寸
- **应用程序 UI**：使用基于 `rem` 的固定类型比例，可以选择在 1-2 个断点处进行调整。流体尺寸调整破坏了基于容器的密集布局所需的空间可预测性
- **营销/内容页面**：通过 `clamp(min, preferred, max)` 使用流体尺寸调整标题和显示文本。保持正文文本固定

### 修复可读性

- 使用 `ch` 单位 (`max-width: 65ch`) 在文本容器上设置 `max-width`
- 根据上下文调整行高：标题更紧（1.1-1.2），正文更宽松（1.5-1.7）
- 稍微增加深色文本的行高
- 确保正文文本至少为 16px / 1rem

### 完善细节

- 对应对齐的数据表和数字使用 `tabular-nums`
- 应用正确的 `letter-spacing`：对于小型大写字母和大写字母稍微打开，对于大显示文本默认或紧密
- 使用语义标记名称（`--text-body`、`--text-heading`），而不是值名称（`--font-16`）
- 设置 `font-kerning: normal` 并在适当的情况下考虑 OpenType 功能

### 重量一致性

- 为每个重量定义明确的角色并坚持下去
- 不要使用超过 3-4 个粗细（常规、中等、半粗体、粗体就足够了）
- 仅加载您实际使用的权重（每个权重都会增加页面加载）

**从不**：
- 使用超过 2-3 个字体系列
- 任意选择尺寸；承诺一定规模
- 将正文文本设置为 16px 以下
- 对正文使用装饰/显示字体
- 禁用浏览器缩放 (`user-scalable=no`)
- 使用 `px` 字体大小；使用 `rem` 尊重用户设置
- 当个性很重要时，默认使用 Inter/Roboto/Open Sans
- 配对相似但不相同的字体（两种几何无衬线字体）

## 验证版式改进

- **层次结构**：您能立即识别标题、正文和标题吗？
- **可读性**：在长段落中阅读正文是否舒适？
- **一致性**：相同角色的元素是否始终具有相同的样式？
- **个性**：排版是否反映了品牌？
- **性能**：网络字体是否可以在不发生布局变化的情况下有效加载？
- **辅助功能**：文本是否符合 WCAG 对比度？可以缩放到200%吗？

当类型自己携带层次结构时，将其交给 `$impeccable polish` 进行最终传递。

## 实时模式签名参数

每个变体必须声明一个控制层次结构比率的 `scale` 参数。通过 `calc(var(--p-scale, 1) * <base>)` 表示变体作用域 CSS 中的所有字体大小，或者更好的是，通过 `clamp(min, calc(var(--p-scale, 1) * Npx), max)` 缩放字体渐变。用户从压抑转变为指挥。

```json
{"id":"scale","kind":"range","min":0.85,"max":1.3,"step":0.05,"default":1,"label":"Scale"}
```

如果变体重复出现在特定配对上，则将配对选择公开为 `steps` 参数（例如“衬线显示 + 无正文”与“单显示 + 无正文”与“全无正文”）。每个分支都通过作用域 CSS 中的 `:scope[data-p-pairing="X"]` 选择器进行路由。

有关完整的参数合约，请参阅 `reference/live.md`。

## 参考资料

下面的部分以前是 `typography.md`，现在是内联的，因此排版流程将其深层排版参考集中在一处。 `bolder.md` 也引用了本节。

### 版式

#### 经典版式原则

##### 垂直节奏

您的行高应该是所有垂直间距的基本单位。如果正文文本在 `16px` 类型 (= 24px) 上具有 `line-height: 1.5`，则间距值应为 24px 的倍数。这创造了潜意识的和谐；文本和空间共享数学基础。

##### 模块化规模和层次结构

常见错误：太多的字体大小太接近（14px、15px、16px、18px...）。这造成了混乱的等级制度。

**使用更少的尺寸并提高对比度。** 5 尺寸系统可满足大多数需求：

|角色 |典型比率|使用案例|
|------|---------------|----------|
| xs | 0.75雷姆|字幕，合法 |
| SM | 0.875雷姆 |辅助 UI、元数据 |
|基地| 1雷姆 |正文 |
| LG | 1.25-1.5雷姆|副标题、引导文本 |
| XL+ | 2-4雷姆 |标题、英雄文本 |

流行的比率：1.25（大三度）、1.333（纯四度）、1.5（纯五度）。选择一个并提交。

##### 可读性和测量

使用 `ch` 单位进行基于字符的测量 (`max-width: 65ch`)。行高与行长成反比：窄列需要更紧的行距，宽列需要更紧的行距。

**不明显**：深色背景上的浅色文本需要在三个轴上进行补偿，而不仅仅是一个轴。将行高提高 0.05–0.1，添加一点字母间距 (0.01–0.02em)，并可选择将字体粗细提高一个档次（常规 → 中等）。三者的感知重量均有所下降；修复所有三个。

**段落节奏**：选择段落之间的空格或首行缩进。从来没有两者兼而有之。数字化通常需要空间；社论/长格式可以证明仅缩进是合理的。

#### 字体选择和配对

战术选择程序和反射拒绝列表位于 **字体选择程序** 和 **反射拒绝列表** 下的 [reference/brand.md](brand.md)（为品牌注册任务加载）。本节的其余部分涵盖了相关知识：抗反射校正、系统字体使用和配对规则。

##### 值得防御的反反射

- 技术/实用简报不需要衬线“为了保暖”。大多数技术工具应该看起来像技术工具。
- 社论/高级简介不需要与每个人现在使用的相同的富有表现力的衬线。 Premium 可以是瑞士现代风格，可以是新怪诞风格，可以是字面意义上的等宽字体，也可以是安静的人文主义风格。
- 儿童产品不需要圆形显示字体。儿童读物使用真实字体。
- “现代”内裤不需要几何无衬线。您能做的最现代的事情就是不要使用其他人正在使用的字体。

**系统字体被低估**：`-apple-system, BlinkMacSystemFont, "Segoe UI", system-ui` 看起来很原生，可以立即加载，并且可读性很高。对于性能 > 个性的应用程序，请考虑这一点。

##### 配对原则

**不明显的事实**：您通常不需要第二种字体。一种精心挑选的多种粗细的字体系列比两种竞争字体创建了更清晰的层次结构。仅当您需要真正的对比度时才添加第二种字体（例如，显示标题+正文衬线）。

配对时，在多个轴上进行对比：
- Serif + Sans（结构对比）
- 几何+人文（个性对比）
- 凝缩显示+宽体（比例对比）

##### 网页字体加载

布局转换问题：字体加载较晚、文本重排以及用户看到内容跳转。这是修复方法：

```css
/* 1. Use font-display: swap for visibility */
@font-face {
  font-family: 'CustomFont';
  src: url('font.woff2') format('woff2');
  font-display: swap;
}

/* 2. Match fallback metrics to minimize shift */
@font-face {
  font-family: 'CustomFont-Fallback';
  src: local('Arial');
  size-adjust: 105%;        /* Scale to match x-height */
  ascent-override: 90%;     /* Match ascender height */
  descent-override: 20%;    /* Match descender depth */
  line-gap-override: 10%;   /* Match line spacing */
}

body {
  font-family: 'CustomFont', 'CustomFont-Fallback', sans-serif;
}
```

[Fontaine](https://github.com/unjs/fontaine) 等工具会自动计算这些覆盖。

**`swap` 与 `optional`**：`swap` 立即显示后备文本，并在 Web 字体到达时进行 FOUT 交换。如果 Web 字体错过了较小的负载预算（~100 毫秒），`optional` 会使用后备，并完全避免转换。当零布局偏移比在慢速网络上看到品牌字体更重要时，请选择 `optional`。

**仅预加载临界粗细**：通常是折叠上方使用的常规粗细正文字体。预加载每个权重所花费的带宽比它节省的带宽要多。

**适用于 3 种以上粗细或样式的可变字体**：单个可变字体文件通常小于三个静态粗细文件，提供分数粗细控制，并与 `font-optical-sizing: auto` 完美搭配。对于 1-2 个重量，静态就可以了。

#### 现代网页版式

##### 流体类型

通过 `clamp(min, preferred, max)` 的流体排版可在视口中平滑地缩放文本。中间值（例如，`5vw + 1rem`）控制缩放速率（较高的 vw = 更快的缩放）。添加 rem 偏移量，使其在小屏幕上不会折叠为 0。

**使用流体类型**：营销/内容页面上的标题和显示文本，其中文本在布局中占主导地位，并且需要跨视口尺寸进行呼吸。

**将固定的 `rem` 比例用于**：应用程序 UI、仪表板和数据密集界面。没有主要的应用程序设计系统（Material、Polaris、Primer、Carbon）在产品 UI 中使用流体类型；具有可选断点调整的固定比例提供了基于容器的布局所需的空间可预测性。即使在营销页面上，正文也应该固定，因为视口之间的尺寸差异太小而无法保证。

**绑定你的夹子()**：保留`max-size ≤ ~2.5 × min-size`。更宽的比例会破坏浏览器的缩放和重排行为，并使大视口感觉页面在喊叫。

**一起缩放容器宽度和字体大小**，因此有效的字符度量在每个视口中保持在 45–75ch 范围内。比其容器加宽更快的标题会偏离顶端的舒适尺寸。

##### OpenType 功能

大多数开发者不知道这些存在。用它们进行抛光：

```css
/* Proper fractions */
.recipe-amount { font-variant-numeric: diagonal-fractions; }

/* Small caps for abbreviations */
abbr { font-variant-caps: all-small-caps; }

/* Disable ligatures in code */
code { font-variant-ligatures: none; }

/* Enable kerning (usually on by default, but be explicit) */
body { font-kerning: normal; }
```

在 [Wakamai Fondue](https://wakamaifondue.com/) 检查您的字体支持哪些功能。

##### 渲染抛光

```css
/* Variable fonts: pick the right optical-size master automatically */
body { font-optical-sizing: auto; }
```

**全大写跟踪**：大写字母在默认间距下太近。为短的全大写标签、眉毛和小标题添加 5–12% 的字母间距（`letter-spacing: 0.05em` 到 `0.12em`）。真正的小盘股（来自`font-variant-caps`）需要同样的处理，稍微温和一些。

#### 版式系统架构

按语义命名标记（`--text-body`、`--text-heading`），而不是按值命名（`--font-size-16`）。在标记系统中包括字体堆栈、尺寸比例、粗细、行高和字母间距。

#### 辅助功能注意事项

除了对比度（有详细记录）之外，请考虑：

- **永远不要禁用缩放**：`user-scalable=no` 会破坏可访问性。如果您的布局在 200% 缩放时损坏，请修复布局。
- **使用 rem/em 作为字体大小**：这尊重用户浏览器设置。正文切勿使用 `px`。
- **最小 16 像素正文**：小于此尺寸会使眼睛疲劳，并且在移动设备上无法进行 WCAG。
- **足够的触摸目标**：文本链接需要填充或行高来创建 44 像素以上的点击目标。

---

**避免**：每个项目超过 2-3 个字体系列。跳过后备字体定义。忽略字体加载性能（FOUT/FOIT）。在正文中使用装饰字体。
