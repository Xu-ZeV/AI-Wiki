设计和迭代生产级前端界面。真实的工作代码、坚定的设计选择、卓越的工艺。

## 设置

在继续之前您必须执行以下步骤：

1. 每个会话运行一次 `node .agents/skills/impeccable/scripts/context.mjs`。如果您已在此对话中看到其输出，请不要重新运行它。该脚本要么将项目的 PRODUCT.md（以及 DESIGN.md，如果存在）打印为 Markdown 块，要么告诉您它丢失了。遵循它打印的任何内容。 **如果它报告 `NO_PRODUCT_MD`，请在执行其他操作之前停止并遵循 `reference/init.md`。** 如果输出以 `UPDATE_AVAILABLE` 指令结束，请遵循它（询问用户一次有关更新的信息，然后继续）。它永远不会阻塞当前任务。
2. 如果用户调用了子命令（`craft`、`shape`、`audit`、`polish`，...），则接下来必须读取 `reference/<command>.md`。非可选。该参考定义了命令的流程；如果没有它，您将跳过用户期望的步骤。
3. 熟悉代码中任何现有的设计系统、约定和组件。至少阅读一个项目文件（CSS/token/主题/代表性组件或页面）。 **即使您在步骤 2 中加载了子命令引用，也是必需的。** 不要重新发明轮子；当可行时使用现有的东西，当用户体验获胜时进行分支。
4. 读取匹配的寄存器参考。 **这是非可选的；跳过它会产生通用输出。**如果项目是营销、登陆页面、活动、长篇内容或作品集（设计就是产品），请阅读 `reference/brand.md`。如果是应用程序 UI、管理、仪表板或工具（设计服务于产品），请阅读 `reference/product.md`。按第一个匹配选择：(1) 任务提示（“登陆页面”与“仪表板”）； (2) 焦点表面（正在处理的页面、文件或路线）； (3) PRODUCT.md 中的 `register` 字段。
5. **如果项目是全新的（在步骤 3 中没有找到现有的 CSS token/主题/承诺的品牌颜色）**，请运行 `node .agents/skills/impeccable/scripts/palette.mjs` 以接收品牌种子颜色和构图指导。这是您的主要品牌颜色的锚点。根据脚本的说明在其周围组成调色板的其余部分（背景、表面、墨水、重音、静音）。始终使用 OKLCH。 **仅当步骤 3 在现有token中找到承诺的品牌颜色时才跳过此步骤；在这种情况下，身份保护会获胜。**

## 设计指导

生成可立即交付的生产级代码，而不是原型或起点。除非用户要求，否则不要走捷径（如有疑问，请询问）。在实现完整的实施之前不要停止（美观、响应灵敏、快速、精确、无错误、符合品牌）。您认真关注细节：制作的每个页面、部分或组件都使用您可用的工具（浏览器屏幕截图、计算机使用等）进行了实际测试。 GPT 能够胜任非凡的工作。不要退缩。

### 一般规则

#### 颜色

- **验证对比度。** 正文与背景的对比度必须达到 ≥4.5:1；大文本（≥18px 或粗体≥14px）需要≥3:1。占位符文本需要相同的 4.5:1，而不是默认的静音灰色。最常见的失败：在接近白色的有色背景上呈现柔和的灰色正文文本。如果对比度非常接近，则将主体颜色撞向渐变的墨水端；浅灰色“为了优雅”是人工智能设计让人难以阅读的最大原因。
- 彩色背景上的灰色文本看起来被冲淡了。使用背景本身色调的较深阴影，或文本颜色的透明度。

#### 版式

- 帽身线条长度为 65–75ch。
- 不要将相似但不相同的字体配对（两个几何无衬线字体，两个人文无衬线字体）。在对比轴上配对（衬线 + 无衬线、几何 + 人文主义）或在多个粗细中使用同一个系列。
- 英雄/显示标题上限：clamp() max ≤ 6rem (~96px)。上面的页面是在喊叫，而不是设计。
- 显示标题字母间距底板：≥-0.04em。任何更紧且字母接触的东西；狭窄，不是“设计的”。
- 在 h1–h3 上使用 `text-wrap: balance` 以获得均匀的线长度； `text-wrap: pretty` 关于长散文以减少孤儿。

您目前错过的一个硬印刷天花板：
- 显示字母间距≥-0.04em。显示屏 H1s 上的默认值 -0.05 到 -0.085em 会使字母接触并且读起来很拥挤。 -0.02 到 -0.03em 对于紧凑的怪诞显示来说已经足够了； -0.04em 是地板。

#### 布局

- 改变节奏的间距。
- 卡片是懒惰的答案。仅当它们确实具有最佳功能时才使用它们。嵌套卡片总是错误的。
- Flexbox 用于 1D，Grid 用于 2D。当 `flex-wrap` 更简单时，不要默认为网格。
- 对于没有断点的响应网格：`repeat(auto-fit, minmax(280px, 1fr))`。
- 构建语义 z-index 比例（下拉菜单 → 粘性 → 模态背景 → 模态 → toast → 工具提示）。切勿使用任意值，例如 999 或 9999。

#### 运动
- 动作应该是有意的，而不是事后才想到的。将其视为构建的一部分。
- 除非确实需要，否则不要对 CSS 布局属性进行动画处理。
- 使用指数曲线缓出（ease-out-quart / quint / expo）。没有弹力，没有弹力。
- 使用库来满足更高级的运动需求（例如，motion、gsap、anime.js、lenis 等）
- 减少运动不是可选的。每个动画都需要一个 `@media (prefers-reduced-motion: reduce)` 替代方案：通常是交叉淡入淡出或即时过渡。
- 交错排列一个列表中的项目是合法的。说明的是统一的反射（每个部分都有一个相同的入口），而不是运动本身；每个揭示内容都应该符合它所揭示的内容。抑制反射绝不是在没有任何动作的情况下发送页面的理由。
- 显示动画必须增强已经可见的默认值。不要在类触发的转换上限制内容可见性；过渡在隐藏选项卡和无头渲染器上暂停，因此显示永远不会触发，并且该部分会显示为空白。
- 高级运动材质不仅仅是变换/不透明度。模糊、背景滤镜、剪辑路径、蒙版和阴影/发光是调色板的一部分，它们可以显着改善效果并保持平滑。

#### 互动

- 在 `overflow: hidden` 或 `overflow: auto` 容器内使用 `position: absolute` 渲染的下拉菜单将被剪裁。使用本机 `<dialog>` / popover API、`position: fixed` 或门户来逃避堆叠上下文。

### 仅限新项目（当不存在先前的工作时）

#### 颜色和主题

- 使用 OKLCH。
- **奶油色/沙色/米色主体背景是 2026 年的饱和 AI 默认值。** 整个暖中性色带（OKLCH L 0.84-0.97，C < 0.06，色调 40-100）读取为奶油色/沙子/纸/羊皮纸，无论你怎么称呼它。token名称如 `--paper`、`--cream`、`--sand`、`--bone`、`--flour`、`--linen`、`--parchment`、`--wheat`、 `--biscuit`、`--ivory` 本身就是说明。如果简介是“温暖、传统、家庭-海岸-意大利”或“杂志-温暖”或“编辑-克制”，请勿将其翻译成近乎白色的暖色调背景；这就是人工智能的举措。选择：(a) 饱和的品牌颜色作为主体颜色（赤土色、深红色、深赭石色、近乎黑色），(b) 色度 0 的纯灰白色（或色度朝向品牌自己的色调，而不是默认的温暖色调），或 (c) 显然是品牌自己的较暗的中色调中性色。品牌的“温暖”是通过口音+排版+图像来承载的，而不是通过身体背景来承载的。
- 有色中性色：向品牌色调添加 0.005–0.015 色度。不要“因为品牌有这样的感觉”而将色调默认为暖色或冷色；这就是跨项目单一文化的举措。
- 选择主题时：黑暗与光明从来都不是默认的。不黑暗“因为工具看起来很酷黑暗。”不轻“为了安全”。选择之前，写下一句物理场景：谁使用这个，在哪里，在什么环境光线下，什么心情。如果这句话不能强行给出答案，那么它就不够具体。添加细节直到完成。
- 在选择颜色之前选择**颜色策略**。承诺轴上的四个步骤：
  - **克制**：中性色 + 一种口音 ≤10%。产品默认；品牌极简主义。
  - **承诺**：一种饱和颜色占表面的 30-60%。身份驱动页面的品牌默认设置。
- **完整调色板**：3-4 个命名角色，每个角色都经过精心使用。品牌活动；产品数据即。
  - **湿透**：表面就是颜色。品牌英雄、活动页面。

### 绝对禁止

匹配并拒绝。如果您要编写其中任何一个，请用不同的结构重写该元素。

- **侧条纹边框。** `border-left` 或 `border-right` 大于 1 像素，作为卡片、列表项、标注或警报上的彩色强调。从来都不是故意的。使用完整边框、背景色调、前导数字/图标或什么都不重写。
- **渐变文本。** `background-clip: text` 与渐变背景相结合。装饰性的，没有任何意义。使用单一纯色。通过重量或尺寸来强调。
- **默认为玻璃形态。** 用于装饰性的模糊和玻璃卡。罕见且有目的的，或者什么都没有。
- **英雄度量模板。** 大数字，小标签，支持统计数据，渐变口音。 SaaS 陈词滥调。
- **相同的卡片网格。** 相同大小的卡片，带有图标 + 标题 + 文本，无限重复。
- **每个部分上方都有微小的大写跟踪眉毛。** 2023 时代的踢脚线（带有宽跟踪的小型全大写文本，每个标题上方有“关于”“流程”“定价”）现在是饱和的 AI 支架；无论简短如何，它都会出现在 55-95% 的世代中，这就是故事的定义。声音是一种被称为“Kicker”的深思熟虑的品牌系统。每个部分的眉毛都是人工智能语法。选择不同的节奏。
- **编号的部分标记作为默认脚手架 (01 / 02 / 03)。** 将 `01 · About / 02 · Process / 03 · Pricing` 放在每个部分上方是更深一层的眉毛比喻：伸手去拿它，因为“登陆页面会执行此操作”，并且您是通过条件反射来搭建脚手架的。当该部分实际上是一个序列（真正的三步过程、有序流程、键入的时间线）并且该顺序包含读者需要的信息时，数字就赢得了自己的位置。一页上经过深思熟虑的编号序列是语音；网站每个部分的眉毛编号都是人工智能语法。
- **溢出其容器的文本。** 长标题词加上大的钳形刻度加上狭窄的网格会导致平板电脑/移动设备上的标题溢出。在每个断点处测试标题副本；如果溢出，则减少限制最大值或重写副本。视口是设计的一部分。

**法典特定缺陷**（最常见的赠品；拒绝并重写）：

- **`border: 1px solid X` + `box-shadow: 0 Npx Mpx ...`，同一元素上 M ≥ 16px**。 “幽灵卡”模式：1px 边框加上按钮和卡片上的柔和宽阴影。不要将它们配对。选择一个（品牌颜色处的单个实心边框，或模糊不超过 8 像素的定义阴影），切勿同时用作装饰。
- **卡/部分/输入上的 `border-radius: 32px+`。** 你过度了。卡片顶部高度为 12–16 像素；全药丸适合标签/按钮。根据 Codex 的规定，在卡片上选择 24/28/32/40px；没有哪个品牌想要“疯狂圆润”。
- **手绘/粗略的 SVG 插图。** 类名，如 `loose-sketch`、`*-sketch`、`doodle`、`wavy`； `feTurbulence` / `feDisplacementMap`“纸粒”过滤器； 5 到 30 个路径的原始场景旨在描绘有形的主题（水獭、桌子和叉子、专辑封面）。所有这些读起来都是业余的，而不是异想天开。如果您无法使用真实资源渲染场景，请不要提供插图。不要尝试使用粗略的 SVG 作为后备。
- **`repeating-linear-gradient(...)` 条纹背景。** `body:before` 或部分背景中的对角条纹是纯粹的法典装饰。不。
- **元批评文案。** 命名一个概念，然后分层添加讽刺修饰语，或者安排一个稻草人来“纠正”它。相反，提出具体的主张。

### AI 倾斜测试

如果有人看到这个界面并毫无疑问地说“人工智能做到了”，那么它就失败了。跨寄存器失败就是上面的绝对禁止。每个参考中都存在特定于寄存器的故障。

**类别反射检查。** 在两个高度运行；第二个抓住了第一个错过的东西。

- **一阶：** 如果有人可以仅从类别中猜出主题+调色板，那么这是第一个训练数据反射。重新设计场景句子和颜色策略，直到从领域中答案不明显为止。
- **二阶：** 如果有人可以从类别加反引用（“AI 工作流程工具不是 SaaS 奶油 → 编辑印刷”、“金融科技不是海军蓝和金色 → 终端原生黑暗模式”）中猜测出美学家族，那么这就是更深一层的陷阱。避免了第一反应；第二个不是。返工，直到两个答案都不明显为止。品牌注册的[反射拒绝美学车道](reference/brand.md) 列表吸引了目前饱和的家庭。

### 路由规则

1. **无争论**：用户在问“我应该做什么？”使菜单能够感知上下文而不是静态的。安装程序已经运行`context.mjs`；如果报告 `NO_PRODUCT_MD` 您已经处于 init（设置）状态，请完成该操作并跳过此操作。否则，运行 `node .agents/skills/impeccable/scripts/context-signals.mjs` 一次并读取其 JSON，然后使用 **2-3 个最高值的下一个命令**，每个命令都有一个从信号中提取的一行原因，然后是完整的菜单（上表，按类别分组）。 **永远不要自动运行命令；该推荐是用户确认的建议。**

对信号进行推理；没有要遵守的分数：
   - `setup.hasDesign` false，而`setup.hasCode` true → `document`（捕获视觉系统）。
   - `critique.latest` 是 `null` → 该项目从未受到批评；对于具有真实表面的设置项目，提供 `$impeccable critique <surface>` 是强有力的默认设置。
   - `critique.latest` 具有低 `score` 或非零 `p0` / `p1` → `polish`（将该快照读取为积压），或者如果快照看起来过时，则重新运行 `critique`。
   - `git.changedFiles` 指向一个表面 → 范围 `audit` 或 `polish` 专门针对这些文件，并命名它们。
   - `devServer.running` true → `live` 可用于浏览器内迭代；如果为 false，则不要以 `live` 开头。
   - 否则，按照 init 的“推荐起点”步骤的意图进行分组（构建新的/改进现有的/以视觉方式迭代），针对 `setup.register` 量身定制。

   **如果 `scan.targets` 非空，则运行 `node .agents/skills/impeccable/scripts/detect.mjs --json <scan.targets joined by spaces>` 一次**（本地文件上的捆绑检测器：无网络，无 npx）。 `scan.via` 告诉您它们是什么：`git-changes`（脏树中的标记/样式文件，最相关的集合）、`source-dir`（例如 `src`、`app`）、`html` 或`root`。将热门歌曲纳入您的选择：许多质量/对比热门歌曲 → `audit` 或 `polish`；特定的斜面系列 → 匹配命令（渐变文本或眉毛 → `quieter` / `typeset`，平面或灰色调色板 → `colorize`，依此类推）。这是一个真实的、当前的信号，胜过猜测。如果检测到错误或树大且慢，请跳过并建议用户自行运行`audit`；永远不要阻止对此的建议。

   保持 2-3 个尖点选择，并输入准确的命令。菜单仍然是后备；推荐的是lede。
2. **第一个单词与命令匹配**（上表或 `pin` / `unpin` / `hooks`）：加载其参考文件并按照其说明进行操作。命令名称后面的所有内容都是目标。
3. **第一个单词不匹配，但意图清楚地映射到一个命令**（例如“修复间距”→ `layout`，“重写此错误消息”→ `clarify`，“颜色感觉平坦”→ `colorize`）：加载该命令的引用并像调用一样继续。如果两个命令可以，询问一次是哪一个。
4. **没有明确的命令匹配**：一般设计调用。使用完整参数作为上下文，应用设置步骤、一般规则和加载的寄存器引用。

此时设置（上下文收集、注册）已经加载；子命令不会重新调用 `$impeccable`。

如果第一个字是 `craft`，安装程序仍然首先运行，但 [reference/craft.md](reference/craft.md) 拥有流程的其余部分。如果安装程序调用 `init` 作为阻止程序，请完成初始化，刷新上下文，然后恢复原始命令和目标。

`teach` 是 `init` 的已弃用别名：如果用户键入它，则加载 [reference/init.md](reference/init.md) 并继续，就像运行 `init` 一样。

## 固定/取消固定

**Pin** 创建一个独立的快捷方式，因此 `$<command>` 直接调用 `$impeccable <command>`。 **取消固定**将其删除。该脚本写入项目中存在的每个线束目录。

```bash
node .agents/skills/impeccable/scripts/pin.mjs <pin|unpin> <command>
```

有效的 `<command>` 是上表中的任何命令。简洁地报告脚本的结果。成功时确认新快捷方式，出错时逐字转发 stderr。

## 钩子

`$impeccable hooks <on|off|status|ignore-rule|ignore-file|ignore-value|reset>` 管理该项目的设计检测器挂钩。在直接 UI 文件编辑后，该挂钩会自动运行检测器，并将结果显示为系统提醒。全流程在[reference/hooks.md](reference/hooks.md)；当用户使用任何参数调用 `$impeccable hooks` 时加载它。
