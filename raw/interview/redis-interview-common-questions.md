# Redis 常见面试题与热门知识点

材料来源：本次 Redis 面试题对话整理。本文记录 Redis 高频面试大纲，覆盖基础、缓存、持久化、过期淘汰、分布式锁、高可用集群和进阶知识点。

## 一、Redis 基础高频题

### Redis 为什么快？

- 内存存储
- 单线程避免频繁上下文切换
- I/O 多路复用
- 高效数据结构
- Redis 6 之后支持网络 I/O 多线程，但命令执行主流程仍以单线程为核心

### Redis 常见数据类型有哪些？

- String：缓存、计数器、分布式锁
- Hash：对象缓存、用户信息
- List：队列、消息列表
- Set：去重、共同关注
- ZSet：排行榜、延迟队列
- Bitmap：签到、在线状态
- HyperLogLog：UV 统计
- Geo：地理位置
- Stream：消息队列、日志流

### String 底层是什么？

- SDS，简单动态字符串。
- 相比 C 字符串，支持 O(1) 获取长度、二进制安全、减少内存重分配。

### Hash、List、Set、ZSet 底层结构？

- Hash：listpack / hashtable
- List：quicklist
- Set：intset / hashtable
- ZSet：listpack / skiplist + dict

### Redis 是单线程还是多线程？

- 命令执行主要是单线程。
- 后台持久化、异步删除、网络 I/O 等可以使用多线程或后台线程。

## 二、缓存场景高频题

### 缓存穿透是什么？怎么解决？

- 查询不存在的数据，绕过缓存打到数据库。
- 解决：缓存空值、布隆过滤器、接口参数校验。

### 缓存击穿是什么？怎么解决？

- 热点 key 过期瞬间，大量请求打到数据库。
- 解决：互斥锁、逻辑过期、热点 key 不设过期、提前刷新。

### 缓存雪崩是什么？怎么解决？

- 大量 key 同时失效，或 Redis 故障。
- 解决：过期时间加随机值、多级缓存、限流降级、Redis 高可用。

### 数据库和缓存一致性怎么保证？

- 常见策略：先更新数据库，再删除缓存。
- 删除失败可用重试队列、MQ、binlog 监听。
- 强一致很难，缓存场景通常追求最终一致。

### 为什么不推荐先更新缓存？

- 并发下容易写入旧数据。
- 缓存更新成本可能高。
- 删除缓存更简单，也更符合懒加载模式。

## 三、持久化高频题

### RDB 和 AOF 区别？

- RDB：快照，全量保存，恢复快，但可能丢数据。
- AOF：追加命令，数据更完整，但文件更大，恢复较慢。
- 实际生产常组合使用。

### AOF 重写是什么？

- 把历史命令压缩成等价的最小命令集。
- 减少 AOF 文件体积，提高恢复效率。

### Redis 宕机会丢数据吗？

- 会，取决于持久化配置。
- RDB 可能丢最近一次快照后的数据。
- AOF `appendfsync everysec` 通常最多丢约 1 秒数据。

## 四、过期与淘汰策略

### Redis key 过期后会立即删除吗？

- 不一定。
- 使用惰性删除 + 定期删除。
- 惰性删除：访问 key 时发现过期再删。
- 定期删除：周期性抽样清理过期 key。

### 内存满了怎么办？

- 看 `maxmemory-policy`。
- 常见策略：
  - `noeviction`：不淘汰，写入报错
  - `allkeys-lru`：所有 key 中淘汰最近最少使用
  - `volatile-lru`：只淘汰设置过期时间的 key
  - `allkeys-lfu`：淘汰低频访问 key
  - `allkeys-random`：随机淘汰

## 五、分布式锁高频题

### Redis 分布式锁怎么实现？

- 加锁：`SET lockKey uniqueValue NX PX expireTime`
- 解锁：用 Lua 脚本判断 value 后删除，避免误删别人的锁。

### 分布式锁有哪些问题？

- 锁过期导致并发执行
- 业务执行时间超过锁 TTL
- 主从切换导致锁丢失
- 需要考虑续期、唯一标识、Lua 解锁、fencing token

### Redisson 看门狗机制是什么？

- Redisson 看门狗机制是分布式锁的自动续期机制。
- 当加锁时没有显式指定 `leaseTime`，Redisson 会给锁设置默认过期时间，并在业务未执行完成时定期续期。
- 只要持有锁的 Redisson 客户端还存活，看门狗就会持续续期，避免业务还没执行完锁就过期。
- 如果服务宕机或客户端异常退出，看门狗停止续期，锁最终会自动过期，避免死锁。
- 如果加锁时指定了明确的 `leaseTime`，一般不会启用看门狗续期，锁会在指定时间后自动释放。

### RedLock 一定安全吗？

- 有争议。
- 普通业务常用单 Redis 或 Redisson。
- 对强一致要求极高的场景，通常更推荐 ZooKeeper、etcd 或带 fencing token 的方案。

## 六、高可用与集群

### Redis 主从复制原理？

- 从节点连接主节点。
- 首次通常全量同步。
- 后续通过复制积压缓冲区做增量同步。
- 使用 PSYNC 支持断线续传。

### Sentinel 是什么？

- 哨兵机制。
- 负责监控、故障转移、主节点选举、通知客户端。

### Redis Cluster 原理？

- 使用 16384 个 hash slot。
- key 根据 CRC16 计算槽位。
- 每个主节点负责一部分槽。
- 节点迁移时可能返回 `MOVED` 或 `ASK`。

### Redis Cluster 为什么不保证强一致？

- 主从复制是异步的。
- 主节点写入后还没同步到从节点就宕机，可能丢数据。

## 七、热门进阶知识点

### Redis 有哪些热门进阶知识点？

- Big Key：单个 key 过大，导致阻塞、迁移慢、删除慢。
- Hot Key：热点 key 请求过高，导致单节点压力过大。
- Lazy Free：异步删除大 key，避免主线程阻塞。
- Pipeline：批量发送命令，减少 RTT。
- Lua 脚本：保证多条命令的原子性。
- 事务：`MULTI / EXEC / WATCH`，但不支持传统数据库那种回滚。
- Pub/Sub：实时发布订阅，但消息不持久。
- Stream：更像消息队列，支持消费组和消息确认。
- 慢查询：`SLOWLOG`。
- 内存分析：`MEMORY USAGE`、`INFO memory`。
- 热点诊断：`redis-cli --hotkeys`、监控 QPS、延迟、命中率。
- 延迟问题：大 key、慢命令、fork、AOF fsync、网络抖动、CPU 打满。
- 安全配置：密码、ACL、TLS、禁止公网裸连、限制危险命令。
